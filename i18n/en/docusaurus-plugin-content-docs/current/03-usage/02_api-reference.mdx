# API Reference

## Core Components

### KlleonOndeviceSdk

The main SDK class that provides all features.

```kotlin
// Manage it as a singleton (recommended)
object SdkConfig {
    val sdk = KlleonOndeviceSdk()
}
val klleonOndeviceSdk = SdkConfig.sdk
```

### KlleonSdkView

A custom Android View for rendering SDK content.

```kotlin
@Composable
fun SdkViewComponent() {
    var workerView by remember { mutableStateOf<KlleonSdkView?>(null) }

    AndroidView(
        factory = { context ->
            KlleonSdkView(context).also { view ->
                workerView = view
            }
        },
        modifier = Modifier.fillMaxSize()
    )
}
```

#### setRenderRotation()

Use this when screen rotation is required, for example on TVs.

```kotlin
klleonSdkView.setRenderRotation(270) // 0, 90, and 270 degrees are supported
```

## ResourceManager

The class responsible for initializing and releasing resources. You must prepare resources with `init()` before calling `play()`.

```kotlin
val resourceManager = ResourceManager()
```

### init()

Copies avatar resources to the cache directory, then performs YUV conversion and native memory loading.

```kotlin
resourceManager.init(
    context: Context,
    mp4FileName: String,
    npzFileName: String,
    styleFileName: String = "",
    faceCropYuvFileName: String = "",
    faceCropYuvMetaFileName: String = "",
    avatarId: String = "",
    onSuccess: () -> Unit,
    onError: (Throwable) -> Unit
)
```

**Parameters:**
| Parameter | Type | Required | Description |
|---------|------|------|------|
| `context` | Context | O | Current context |
| `mp4FileName` | String | O | Avatar MP4 file name (in assets) |
| `npzFileName` | String | O | Avatar NPZ file name (in assets) |
| `styleFileName` | String | X | Style file name (default: "") |
| `faceCropYuvFileName` | String | X | Pre-extracted face crop YUV file name (default: ""). When provided, the `warpAffine` step is skipped to shorten the inference path (LIPSYNC-007, v0.6.0) |
| `faceCropYuvMetaFileName` | String | X | Face crop YUV meta file name (default: ""). Used together with `faceCropYuvFileName` |
| `avatarId` | String | X | Avatar ID. When re-entering the same avatar, buffers are reused and `onSuccess` returns immediately |
| `onSuccess` | () -> Unit | O | Callback for when resources are ready |
| `onError` | (Throwable) -> Unit | O | Error callback |

**Example:**
```kotlin
resourceManager.init(
    context = this,
    mp4FileName = "loop_sample.mp4",
    npzFileName = "loop_sample.npz",
    styleFileName = "loop_sample.style",
    avatarId = "character_001",
    onSuccess = {
        // Ready — play() is a suspend function, so call it from a coroutine
        CoroutineScope(Dispatchers.IO).launch {
            klleonOndeviceSdk.play(context, sdkView, sdkKey, avatarId, language)
        }
    },
    onError = { error ->
        Log.e("SDK", "Failed to prepare resources", error)
    }
)
```

:::info Buffer reuse
Calling `init()` again with the same avatar (`avatarId`) reuses the already prepared buffers and returns `onSuccess` immediately. When switching to a different avatar, the previous buffers are released and new ones are allocated.
:::

### deinit()

Releases the native YUV buffer memory and resets the resource state.

```kotlin
resourceManager.deinit()
```

:::tip Idempotent
`deinit()` is safe to call multiple times. Calling it when already released is a no-op.
:::

### Call Rules

1. **`init()`** — Call it once avatar selection is complete. Previous buffers are released automatically when the avatar changes.
2. **`play()`** — Can be called only after the `onSuccess` callback of `init()` arrives
3. **`deinit()`** — Call it when the app fully terminates. `finish()` keeps the buffers to optimize re-entry into the same avatar.

## SDK Methods

### play()

Starts AI avatar video playback. It is a `suspend` function, so it must be called from a coroutine.

v0.7.0+ added the `sttMode` parameter, v0.8.0+ changed its default to `STT_ONLY`, and v0.12.0+ added the `useMelSpectrogram` parameter.

```kotlin
suspend fun play(
    context: Context,
    klleonSdkViewInstance: KlleonSdkView?,
    sdkKey: String,
    avatarId: String,
    language: String,
    sttMode: SttMode = SttMode.STT_ONLY,
    useMelSpectrogram: Boolean = false,
)
```

**Parameters:**
| Parameter | Type | Required | Description |
|---------|------|------|------|
| `context` | Context | O | Current context |
| `klleonSdkViewInstance` | KlleonSdkView? | O | Rendering view |
| `sdkKey` | String | O | SDK authentication key |
| `avatarId` | String | O | AI avatar ID |
| `language` | String | O | Language code (`ko_kr`, `en_us`, `ja_jp`) |
| `sttMode` | [SttMode](#sttmode) | X | STT result delivery mode (default `STT_ONLY` — the app calls `sendMessage()` explicitly after receiving the result) |
| `useMelSpectrogram` | Boolean | X | Lip-sync pipeline mode (v0.12.0+, default `false`). When `true`, the SDK starts on the MEL spectrogram path and the [cached speech API](#cached-speech-api) becomes available |

When `voiceRecognitionMode` is `ALWAYS_ON` (the v0.8.0+ default), the microphone session starts automatically after `play()`. A separate `startAlwaysOnListening()` call is unnecessary.

**Example:**
```kotlin
CoroutineScope(Dispatchers.IO).launch {
    workerView?.let { view ->
        klleonOndeviceSdk.play(
            context = this@Activity,
            klleonSdkViewInstance = view,
            sdkKey = "YOUR_SDK_KEY",
            avatarId = "character_001",
            language = "ko_kr",
            // sttMode = SttMode.STT_ONLY,  // v0.8.0+ default (can be omitted)
        )
    }
}
```

### connect()

Performs a WebSocket reconnection.

```kotlin
klleonOndeviceSdk.connect()
```

### finish()

Stops the SDK and cleans up all resources. It is a `suspend` function, so it must be called from a coroutine.
Internal buffers are kept for reuse when re-entering the same avatar (soft reset).

```kotlin
// When the Activity is destroyed
CoroutineScope(Dispatchers.Default).launch {
    klleonOndeviceSdk.finish()
}
```

### awaitFinish()

Waits until an in-progress `finish()` completes. If no termination is in progress, it returns immediately.
When calling `play()` again quickly after `finish()`, call this before `ResourceManager.init()` to prevent resource contention.

```kotlin
// On fast re-entry
CoroutineScope(Dispatchers.Default).launch {
    klleonOndeviceSdk.awaitFinish()  // Wait for the previous termination to complete
    ResourceManager.init(context, ...)
}
```

## Chat API

Calls biz-backend `/api/v1/chat`. The SDK handles HTTP, authentication, image URL absolutization, and parsing; the caller only receives blocks. The raw app secret key stays inside the SDK.

### chat()

```kotlin
suspend fun chat(
    context: Context,
    text: String,
    lang: String = "ko",
    sessionId: String? = null,
): ChatResult
```

| Parameter | Type | Required | Description |
|---------|------|------|------|
| `text` | String | O | User input |
| `lang` | String | X | Response language (`ko` / `en` / `ja`) |
| `sessionId` | String? | X | Multi-turn context key for one conversation. Generate a UUID when a conversation starts, reuse it for every call in that conversation, and discard it at the end. If `null`, the server replies without history |

A `play()` session is not required — only a preceding `ResourceManager.init()`. The result is `ChatResult.Success(blocks)` or `ChatResult.Error(error, message)`, and `ChatBlock` is `Text` / `Image` / `Unknown` (an unknown type falls back to `Unknown`, guaranteeing forward compatibility).

### ChatBlock.Text.speech

v0.13.0+. A text block may carry a **reference to the server's cached audio**.

```kotlin
data class Text(
    val content: String,
    val speech: CachedSpeechRef? = null,
) : ChatBlock()

data class CachedSpeechRef(
    val fileName: String,   // e.g. "Mn38h2DpWyJ2.pcm"
    val format: String?,    // e.g. "pcm_s16le_16k"
)
```

A non-null `speech` means **the server has a recording for this answer**. It is not an instruction to play it — it is a **lookup key** for checking whether the device already downloaded that file. If it is absent, speak with TTS as usual.

```kotlin
val ref = block.speech
if (ref != null && myCache.has(ref.fileName)) {
    klleonOndeviceSdk.speakCachedPcm16Le(myCache.read(ref.fileName))
} else {
    klleonOndeviceSdk.sendMessageEcho(block.content)   // TTS fallback
}
```

:::info
`fileName` is a deterministic hash of the answer text. **Do not compute it yourself — use the value the server returned as the lookup key.** Duplicating the hashing rule will silently drift. `format` is supplementary; `fileName` is the only key that matters.
:::

### setChatBaseUrl()

v0.13.0+. Changes the server that [chat()](#chat) requests go to. Intended for local and staging verification.

```kotlin
fun setChatBaseUrl(url: String?)
```

Pass `null` to restore the SDK default. Call it **before** `ResourceManager.init()` so that the boot-time cached-audio sync also targets the chosen server.

## Cached Speech API

v0.12.0+. Plays pre-prepared PCM audio instantly without a server round trip. Use it to remove response latency for fixed lines such as greetings and guidance messages.

**Prerequisite**: Works only in a session started with `play(useMelSpectrogram = true)`. Calling it in any other session returns `Result.failure(IllegalStateException)`.

### speakCachedAsset()

Plays a PCM file from the app's assets.

```kotlin
suspend fun speakCachedAsset(assetName: String): Result<Int>
```

| Parameter | Type | Required | Description |
|---------|------|------|------|
| `assetName` | String | O | PCM file name in assets (16 kHz mono int16 LE) |

The return value is the number of samples used for the speech. On failure it returns `Result.failure`.

### speakCachedPcm16Le()

Plays PCM bytes held in memory.

```kotlin
suspend fun speakCachedPcm16Le(pcmBytes: ByteArray): Result<Int>
```

| Parameter | Type | Required | Description |
|---------|------|------|------|
| `pcmBytes` | ByteArray | O | 16 kHz mono int16 little-endian PCM (fixed at 16 kHz per the cache contract) |

### Cache store (v0.13.0+)

The SDK stores cached PCM and answers whether it holds a given file. Where [speech](#chatblocktextspeech) in the `chat()` response tells you **whether the server has it**, this tells you **whether this device has it**. Files live in app-private internal storage, inaccessible to other apps.

```kotlin
fun hasCachedSpeech(context: Context, fileName: String): Boolean
fun importCachedSpeech(context: Context, fileName: String, pcmBytes: ByteArray): Boolean
fun cachedSpeechCount(context: Context): Int
suspend fun speakCachedFile(fileName: String): Result<Int>
```

| Function | Description | Requires `play()` |
|------|------|------|
| `hasCachedSpeech` | Whether it is held. An in-memory lookup, so it is safe to call on every response | X |
| `importCachedSpeech` | Stores raw 16 kHz mono int16 LE PCM. Overwrites an existing name | X |
| `cachedSpeechCount` | Number held (diagnostics) | X |
| `speakCachedFile` | Speaks a held file by name | **O** (`useMelSpectrogram = true`) |

### speakAnswer()

v0.13.0+. **The SDK performs the two-stage decision and the fallbacks for you.** Prefer this over composing the functions above yourself.

```kotlin
suspend fun speakAnswer(context: Context, block: ChatBlock.Text): Result<SpeechSource>

enum class SpeechSource { CACHED, TTS, ERROR_NOTICE }
```

| Stage | Condition | Result |
|---|---|---|
| 1 | The server returned a cached file name **and** the device holds it | `CACHED` — local PCM, no server round trip |
| 2 | Otherwise, or cached playback failed | `TTS` — the existing WebSocket speech |
| 3 | TTS also failed (socket dropped, etc.) | `ERROR_NOTICE` — notice audio only. **The answer is not delivered** |

```kotlin
val first = blocks.filterIsInstance<ChatBlock.Text>().firstOrNull()
first?.let { block ->
    when (klleonOndeviceSdk.speakAnswer(context, block).getOrNull()) {
        SpeechSource.CACHED -> { /* cache hit */ }
        SpeechSource.TTS -> { /* normal path */ }
        SpeechSource.ERROR_NOTICE -> { /* answer not delivered — consider an on-screen notice */ }
        null -> { /* even the notice audio failed */ }
    }
}
```

:::info
Stage 3 exists to **prevent silence**. If the user speaks and hears nothing at all, the avatar appears to have ignored them.

Stages 1 and 3 work only in a `play(useMelSpectrogram = true)` session. Other sessions can use stage 2 only, and `Result.failure` is returned when it fails.
:::

**If you compose it yourself** (not using `speakAnswer`):
```kotlin
val ref = block.speech                                            // stage 1 — does the server have it
if (ref != null && sdk.hasCachedSpeech(context, ref.fileName)) {  // stage 2 — does this device have it
    sdk.speakCachedFile(ref.fileName)                             // local PCM playback
} else {
    sdk.sendMessageEcho(block.content)                            // TTS fallback
}
```

### syncCachedSpeech()

v0.13.0+. Reconciles the server's cached-audio list with what the device holds — downloads only what is missing or updated, and removes what disappeared from the server. Call it whenever you like, such as at app start. No `play()` session is required.

```kotlin
suspend fun syncCachedSpeech(
    context: Context,
    onProgress: ((done: Int, total: Int) -> Unit)? = null,
): Result<CachedSpeechSyncResult>

data class CachedSpeechSyncResult(
    val remoteTotal: Int, val downloaded: Int, val removed: Int, val failed: Int,
)
```

```kotlin
scope.launch {
    klleonOndeviceSdk.syncCachedSpeech(context) { done, total ->
        updateProgress(done, total)
    }.onSuccess { Log.i(TAG, "Sync: $it") }
}
```

:::info
**Assets are fetched from the server set by [setChatBaseUrl](#setchatbaseurl).** File names come from the `chat()` response, so the assets must be on the same server for the names to match.

Re-download is decided by the server's `updated_at` — the file name is a hash of the answer text, so re-recording the same sentence keeps the same name.

Interrupting is safe (the server is stateless). Calling it again resumes with what is left. If a sync is already running, it fails immediately. Individual file failures are counted in `failed` and **do not abort the whole run**.
:::

:::info
`importCachedSpeech` rejects file names containing path separators or `..`. Passing `updatedAt` lets the next sync treat that file as current (omit it and the file is treated as unknown-version and re-downloaded once).

Even if a name is in the held list, a missing file makes `speakCachedFile` fail and removes it from the list automatically. Fall back to TTS in that case — a `true` from `hasCachedSpeech` does not guarantee playback.
:::

### isCachedSpeechReady()

Checks whether cached speech is available.

```kotlin
fun isCachedSpeechReady(): Boolean
```

**Example:**
```kotlin
CoroutineScope(Dispatchers.IO).launch {
    klleonOndeviceSdk.play(
        context = this@Activity,
        klleonSdkViewInstance = view,
        sdkKey = "YOUR_SDK_KEY",
        avatarId = "character_001",
        language = "ko_kr",
        useMelSpectrogram = true,          // Prerequisite for cached speech
    )

    if (klleonOndeviceSdk.isCachedSpeechReady()) {
        klleonOndeviceSdk.speakCachedAsset("greeting_ko.pcm")
            .onFailure { Log.w(TAG, "Cached speech failed: ${it.message}") }
    }
}
```

## Runtime Configuration (RuntimeConfig)

v0.12.0+. SDK behavior toggles that can be changed even during playback.

### audioNonStreaming

```kotlin
RuntimeConfig.audioNonStreaming = true   // Default
```

- `true` (default): **non-streaming** — receives all audio for one utterance and then plays it at once. Dropouts caused by mid-speech buffer underruns disappear, at the cost of a longer delay before the first sound.
- `false`: **streaming** — plays server audio chunks as they arrive. Latency is low, but on slow networks underruns can make speech choppy.

The value is **captured when speech starts** and stays fixed until that utterance ends (toggling mid-speech does not mix modes).

> The default is non-streaming from v0.12.0. Set it to `false` if you need the playback behavior of previous versions.

## Wakeword API

Detects registered wakewords in STT results and delivers a callback. When a wakeword matches, that STT result is excluded from normal conversation input (`STT_RESULT`).

:::note Standby integration policy
Wakeword matching is **disabled** by default. It is enabled automatically when `enterStandby()` is called and disabled automatically when `exitStandby()` is called. Even if you register wakewords with `registerWakewords()`, matching works only after entering standby mode.
:::

:::info STT language and wakewords
The language set through `play(language)` or `sendChangeLanguage(language)` is also applied as the STT recognition language. Because wakeword matching operates on the STT results of that language, you must **register wakewords that the STT of each language can recognize**.

Examples:
- Korean STT → wakewords with Korean pronunciation such as `"영어"`, `"일본어"`, `"니혼고"`
- Japanese STT → Japanese-recognizable wakewords such as `"韓国語"`, `"英語"`, `"コリアン"`
- English STT → English wakewords such as `"Korean"`, `"Japanese"`
:::

### registerWakewords()

Registers wakewords. This replaces all existing wakewords. Registration alone does not enable matching; it is enabled when `enterStandby()` is entered.

```kotlin
fun registerWakewords(wakewords: Map<String, String>)
```

**Parameters:**
| Parameter | Type | Description |
|---------|------|------|
| `wakewords` | Map\<String, String\> | A wakeword → tag map. When a wakeword is detected, the tag value is delivered through the callback |

**Example:**
```kotlin
// Register wakewords for language switching
klleonOndeviceSdk.registerWakewords(mapOf(
    "니혼고" to "ja_jp", "일본어" to "ja_jp",
    "잉글리쉬" to "en_us", "영어" to "en_us",
    "한국어" to "ko_kr", "코리안" to "ko_kr",
))
```

### clearWakewords()

Clears all registered wakewords. After clearing, wakeword matching does not run and every STT result is delivered as `STT_RESULT`.

```kotlin
klleonOndeviceSdk.clearWakewords()
```

### wakewordDetected

A `SharedFlow` that emits wakeword matching results.

```kotlin
val wakewordDetected: SharedFlow<WakewordResult>
```

**WakewordResult:**
| Field | Type | Description |
|------|------|------|
| `wakeword` | String | The matched wakeword text (for example, `"니혼고"`) |
| `tag` | String | The tag specified at registration (for example, `"ja_jp"`) |
| `fullText` | String | The full text recognized by STT |

**Example:**
```kotlin
// Switch language when a wakeword is detected
LaunchedEffect(Unit) {
    klleonOndeviceSdk.wakewordDetected.collect { result ->
        // result.wakeword = "니혼고", result.tag = "ja_jp"
        klleonOndeviceSdk.sendChangeLanguage(result.tag)
    }
}
```

:::tip
The SDK does not care what a wakeword means. You are free to define the tag values, and any string can be used besides language codes — for example `"mode_quiet"` or `"stop"`.
:::

## Standby API

### enterStandby()

Enters standby mode. It cleans up the whole pipeline (draining queues, discarding audio buffers, resetting timing) and then pauses video decoding and audio playback. Resources are kept.

```kotlin
klleonOndeviceSdk.enterStandby()
```

### exitStandby()

Exits standby mode. Video decoding and audio playback resume.

```kotlin
klleonOndeviceSdk.exitStandby()
```

### isStandby()

Checks whether standby mode is active.

```kotlin
val isStandby: Boolean = klleonOndeviceSdk.isStandby()
```

### setIdleTimeout(timeoutMs)

Enables the idle timeout. After the avatar finishes speaking (TTS_END), `enterStandby()` is called automatically once the specified period of inactivity elapses. Standby is entered after the `STANDBY_ENTER` event is published through `sdkState`.

```kotlin
// Default 60 seconds
klleonOndeviceSdk.setIdleTimeout()

// Custom timeout (30 seconds)
klleonOndeviceSdk.setIdleTimeout(30_000L)
```

:::info
It can be called at any point before or after `play()`. If you don't call it, the automatic standby feature stays disabled.
:::

### disableIdleTimeout()

Disables the idle timeout. Any active timer is cancelled.

```kotlin
klleonOndeviceSdk.disableIdleTimeout()
```

### avatarState: StateFlow\<AvatarState\>

Available from v0.10.3. Exposes the avatar's speech lifecycle state as a typed Flow. It is the speech state extracted from the general-purpose `sdkState` string stream.

```kotlin
enum class AvatarState {
    IDLE,       // Idle
    PREPARING,  // Preparing a response
    SPEAKING,   // Speaking
}
```

```kotlin
klleonOndeviceSdk.avatarState.collect { state ->
    when (state) {
        AvatarState.IDLE -> { /* Idle UI */ }
        AvatarState.PREPARING -> { /* Show "preparing a response" */ }
        AvatarState.SPEAKING -> { /* Show "speaking" */ }
    }
}
```

### isResponding: StateFlow\<Boolean\>

`true` when the avatar is preparing a response or speaking. From v0.10.3 it is derived from `avatarState != IDLE` (that is, `true` for `PREPARING` or `SPEAKING`, and `false` for `IDLE`). The boolean behavior is unchanged from before.

```kotlin
// Check the current value
if (klleonOndeviceSdk.isResponding.value) {
    // The avatar is responding
}

// Subscribe as a Flow
klleonOndeviceSdk.isResponding.collect { responding ->
    // Update the UI
}
```

## Speech Recognition API

Since v0.8.0, the default for `voiceRecognitionMode` is `ALWAYS_ON` and the default for `sttMode` is `STT_ONLY`. The microphone session starts automatically right after `play()`, and STT results are delivered through the `STT_RESULT` chat_type of `sdkState` — the app then calls `sendMessage()` after post-processing.

| API | Mode | Behavior | Use case |
|---|---|---|---|
| `startAlwaysOnListening` ⭐ | `ALWAYS_ON` | Keeps the session without VAD/gating and sends all audio to STT | Always-on listening, continuous conversation (recommended) |
| `startVoiceRecognition` ⚠️ Deprecated | `DISCRETE` | Ends automatically when VAD detects silence (one utterance at a time) | Push-to-talk, one-off commands — scheduled for removal in v0.9.0+ |

### SttMode

The enum for the STT result delivery mode (v0.7.0+). Set at `play()` time.

```kotlin
enum class SttMode {
    /** STT only (default, v0.8.0+) — returns the result to the app UI only. Not sent to the server LLM. */
    STT_ONLY,

    /** Sends the STT result to the server immediately — app UI + server LLM. */
    @Deprecated("Scheduled for removal in v0.9.0+. Use STT_ONLY + an explicit sendMessage() call.")
    AUTO_SEND_TO_SERVER,
}
```

Usage:
- **STT_ONLY** (default): the app receives the `STT_RESULT` chat_type from `sdkState` → filters/validates → calls `sendMessage()` explicitly.
- **AUTO_SEND_TO_SERVER** (deprecated): user speech → immediate AI response (compatible with the previous flow).

### voiceRecognitionMode

Sets the speech recognition mode. It must be set before calling `play()`.

```kotlin
// The v0.8.0+ default is ALWAYS_ON, so this is usually unnecessary
klleonOndeviceSdk.voiceRecognitionMode = VoiceRecognitionMode.ALWAYS_ON
```

**Modes:**
| Mode | Description |
|------|------|
| `ALWAYS_ON` | Always listening (v0.8.0+ default). Starts automatically after `play()` and keeps the session |
| `DISCRETE` | One-shot mode. Start/stop manually with `startVoiceRecognition()` (deprecated flow) |

### startAlwaysOnListening()

Starts ALWAYS_ON listening. When `voiceRecognitionMode = ALWAYS_ON`, it is called automatically inside `play()`, so you usually don't need to call it externally. Call it explicitly only in special flows such as re-granting a previously denied permission.

```kotlin
val success: Boolean = klleonOndeviceSdk.startAlwaysOnListening()
```

### isAutoListening()

Checks whether ALWAYS_ON automatic listening is active.

```kotlin
val isListening: Boolean = klleonOndeviceSdk.isAutoListening()
```

### startVoiceRecognition()

⚠️ **Deprecated (v0.8.0+)** — use `startAlwaysOnListening()` instead. Scheduled for removal in v0.9.0+.

Starts DISCRETE mode speech recognition. It starts microphone recording and sends a START_VOICE signal over WebSocket. When silence is detected, recording ends automatically and an END_VOICE signal is sent.

```kotlin
@Deprecated("DISCRETE mode speech recognition is scheduled for removal in v0.9.0+")
fun startVoiceRecognition(
    config: SilenceDetectionConfig = SilenceDetectionConfig.default()
): Boolean
```

**Parameters:**
- `config`: silence detection settings (optional, default: `SilenceDetectionConfig.default()`)

**Return value:** whether it succeeded (Boolean)

You must set `sdk.voiceRecognitionMode = VoiceRecognitionMode.DISCRETE` explicitly before calling it (because the v0.8.0+ default is ALWAYS_ON).

### stopVoiceRecognition()

Stops speech recognition. Used for manual termination in the DISCRETE mode flow.

```kotlin
klleonOndeviceSdk.stopVoiceRecognition()
```

### isVoiceRecognizing()

Checks whether speech recognition is in progress.

```kotlin
val isRecognizing: Boolean = klleonOndeviceSdk.isVoiceRecognizing()
```

## State Management

### sdkState

A SharedFlow that emits SDK state updates as JSON strings.

```kotlin
klleonOndeviceSdk.sdkState: SharedFlow<String>
```

**Usage:**
```kotlin
klleonOndeviceSdk.sdkState.collect { state ->
    val messageToAdd = try {
        val json = JSONObject(state)
        json.getString("message")
    } catch (t: Throwable) {
        state.toString()
    }

    // Handle the state update
    updateUI(messageToAdd)
}
```

**State format (JSON):**
```json
{
  "message": "",
  "chat_type": "ACTIVATE_VOICE",
  "time": "2025-09-03T05:42:08.394975295",
  "id": "99dd3ab3-53c4-4418-bee4-b1fbaea272aa"
}
```

**Key chat_type values:**
| chat_type | Description |
|-----------|------|
| `WSS_OPEN` | WebSocket connection succeeded |
| `WSS_FAILURE` | WebSocket connection failed |
| `WSS_CLOSING` | WebSocket connection closing |
| `WSS_CLOSED` | WebSocket connection closed |
| `WSS_RETRY_OVER` | Maximum retries exceeded |
| `WSS_NOT_CONNECTED` | Not connected |
| `ACTIVATE_VOICE` | Ready to receive voice input |
| `TEXT` | Text response received from the server |
| `RESPONSE_IS_ENDED` | Server response stream ended |
| `TTS_START` | TTS audio playback started |
| `TTS_END` | TTS audio playback finished (used to detect the end of speech) |
| `SHOW_AVATAR` | Avatar ready to be displayed |
| `USER_SPEECH_STARTED` | User speech start detected |
| `USER_SPEECH_STOPPED` | User speech end detected |
| `PREPARING_RESPONSE` | Server response being prepared |
| `STT_RESULT` | Final speech recognition result |
| `STT_PARTIAL` | Interim speech recognition result |
| `STT_ERROR` | Speech recognition error |
| `STT_STATUS` | Speech recognition status change notification (preparing/reconnecting/ready) |
| `WORKER_DISCONNECTED` | Socket connection closed |
| `SPEECH_START` | Avatar speech started |
| `SPEECH_END` | Avatar speech ended |
| `STOP_RESPONSE_MESSAGE` | Interrupt the avatar's current speech |

#### STT_STATUS Details

Notifies you of transient state changes in the speech recognition session. It occurs with STT providers that use token-based authentication (such as Azure).

| Status | message value | Meaning | When it occurs |
|------|------------|------|-----------|
| `Preparing` | `음성 인식 준비 중` | Recognition start is delayed while waiting for a token | When speech recognition starts before a token has been received |
| `Recovering` | `음성 인식 재연결 중` | Waiting for token reissue after an authentication failure | When the authentication token expires during recognition |
| `Ready` | `음성 인식 준비 완료` | Recovery complete, speech recognition resumed | When recognition restarts after the token is reissued |

:::tip
`STT_STATUS` is a transient state notification. Show a toast or similar guidance to the user when you receive `음성 인식 준비 중` or `음성 인식 재연결 중`, and dismiss it naturally when `음성 인식 준비 완료` arrives.
:::

## SilenceDetectionConfig

Configures silence detection behavior during speech recognition.

```kotlin
import io.klleon.ondevice.audio.oboe.SilenceDetectionConfig
```

**Fields:**
| Field | Type | Default | Description |
|------|------|--------|------|
| `silenceThreshold` | Float | 0.02 | Level threshold for deciding silence |
| `speechThreshold` | Float | 0.05 | Level threshold for deciding speech |
| `speechTimeoutMs` | Long | 5000 | Wait time for voice input (ms) |
| `silenceTimeoutMs` | Long | 2000 | Silence detection time after speech (ms) |
| `maxRecordingTimeMs` | Long | 60000 | Maximum recording time (ms, 0 = unlimited) |
| `preBufferMs` | Int | 300 | Audio retained before speech starts (ms) |
| `preBufferDelayMs` | Long | 300 | Pre-buffer flush delay (ms) |

**Presets:**
| Preset | Characteristics |
|--------|------|
| `SilenceDetectionConfig.default()` | Default settings |
| `SilenceDetectionConfig.fast()` | Fast response (speechTimeout 3 s, silenceTimeout 1.5 s) |
| `SilenceDetectionConfig.longSpeech()` | Long speech (speechTimeout 7 s, silenceTimeout 3 s, maxRecording 120 s) |
| `SilenceDetectionConfig.noisyEnvironment()` | Noisy environments (raised thresholds: silence 0.05, speech 0.10) |

**Example:**
```kotlin
// Using a preset
klleonOndeviceSdk.startVoiceRecognition(SilenceDetectionConfig.fast())

// Custom settings
val config = SilenceDetectionConfig.default().copy(
    speechTimeoutMs = 3000L,
    maxRecordingTimeMs = 120_000L
)
klleonOndeviceSdk.startVoiceRecognition(config)
```

## Error Handling

All SDK methods should be wrapped in try-catch blocks:

```kotlin
try {
    klleonOndeviceSdk.sendMessage(message)
} catch (e: Exception) {
    Log.e("KlleonSDK", "Operation failed", e)
    // Handle the error appropriately
}
```

## Lifecycle Management

`play()` and `finish()` are `suspend` functions. In the Activity lifecycle, wrap them in a coroutine.

```kotlin
class ChatActivity : ComponentActivity() {
    private val sdk = SdkConfig.sdk

    override fun onDestroy() {
        super.onDestroy()
        // finish() is a suspend function, so run it from a coroutine
        CoroutineScope(Dispatchers.Default).launch {
            sdk.finish()  // Stop the SDK (buffers are kept for reuse)
        }
        ResourceManager.deinit()  // Call this only when the app fully terminates
    }
}
```

### Fast Re-entry (finish → play)

Calling `play()` immediately after `finish()` can cause resource contention.
Use `awaitFinish()` to proceed only after the previous termination completes:

```kotlin
// When starting a new avatar from the character selection screen
CoroutineScope(Dispatchers.Default).launch {
    sdk.awaitFinish()  // Wait if a previous finish() is in progress
    ResourceManager.init(context, mp4, npz, style, avatarId,
        onSuccess = { /* Start ChatActivity → play() */ },
        onError = { /* Handle the error */ }
    )
}
```
