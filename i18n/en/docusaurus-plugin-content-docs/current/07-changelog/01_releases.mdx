# Release Notes

Changes in the Klleon Ondevice SDK by version.

---

## v0.13.0 (Latest)

**Release date**: September 2026

### Breaking Changes

- **The `scope` parameter was removed from `chat()`.** The server dropped it from the contract —
  the index is selected from the authenticated tenant, so the value was never used.

  :::danger Positional calls compile fine and fail silently
  ```kotlin
  sdk.chat(ctx, text, "sony_booth", "ko")   // 0.12.x — compiles. "sony_booth" now binds to lang
  sdk.chat(ctx, text, lang = "ko")          // 0.13.0
  ```
  Only code that passed it as a named argument (`scope = ...`) fails to compile. **Audit every**
  `chat(` call site when upgrading.
  :::

- **`ChatBlock.Text` gained a `speech: CachedSpeechRef?` field.** Source compatible, but the
  `copy`/`componentN` signatures changed, making it **binary incompatible** — recompile required.

### New Features

- **Cached speech** — plays a recording the server synthesized in advance, so there is no TTS
  round trip (measured: 0.7 s from STT to speech on a cache hit, versus 2.1–3.0 s via TTS).
  - `speakAnswer(context, block)` — **three-stage fallback**: cached PCM → TTS → notice audio.
    It exists to prevent the user speaking and hearing nothing back
  - `syncCachedSpeech()` · `hasCachedSpeech()` · `importCachedSpeech()` ·
    `cachedSpeechCount()` · `speakCachedFile()` — cache store
  - `ChatBlock.Text.speech` — a **lookup key** telling you the server holds a recording for this answer
- `setChatBaseUrl(url)` — switches the chat and asset server (for local server verification)

### Behavior Changes

- `ResourceManager.init()` now synchronizes cached audio with the server automatically. The
  signature is unchanged. If the server holds no assets, the sync ends with zero downloads and
  speech falls back to the existing TTS.

### Bug Fixes

- Attestation could fail **permanently** on a reinstalled device because of a dead keystore key.
  If `Cipher.init` fails, the alias is now deleted and regenerated once
- An empty manifest caused the entire local cache to be marked for deletion (guard added)
- Input arriving while the avatar was preparing to speak could start a second turn, making the
  avatar speak two answers back to back
- Cached speech sat outside the avatar response cycle, breaking the `TTS_START`/`TTS_END` pairing

## v0.12.1

**Release date**: August 2026

### Bug Fixes
- **`setIdleTimeout()` stopped working permanently when the server never responded after a send.**
  `sendMessage()`/`sendMessageEcho()` only stopped the idle timer and relied on server events to
  restart it, so if the server returned nothing, `STANDBY_ENTER` never fired for that session.
  Sending now switches to a response watchdog, so it converges within `timeoutMs` even with no
  response. The watchdog occupies the leading portion of the `timeoutMs` budget (up to 20 s), so
  the total wait does not increase.
- Added `RATE_LIMIT`, `WSS_FAILURE`, and `WSS_RETRY_OVER` to the idle-timer restart triggers.
  `RATE_LIMIT` in particular is a case where the server responds instead of `PREPARING_RESPONSE`,
  so the recovery signal was missing at exactly the moment the timer was stopped.

### Internal Changes
- Extracted the idle-timer restart trigger list into a single source. The progress signals and
  the termination signals had diverged into two copies, causing the triggers to drift.

### Compatibility
No public API signature changes. Only apps using `setIdleTimeout()` see a behavior difference —
previously the standby screen was not entered when the server did not respond; now it is.

## v0.12.0

**Release date**: August 2026

### New Features
- Added the `useMelSpectrogram: Boolean = false` parameter to `play()` — a mode switch that moves to the MEL-spectrogram-based lip-sync pipeline. `false` (the default) keeps the existing AUDIO_FEATURE path.
- Added the cached speech API: `speakCachedAsset(assetName: String): Result<Int>`, `speakCachedPcm16Le(pcmBytes: ByteArray): Result<Int>`, `isCachedSpeechReady(): Boolean`. Plays pre-prepared PCM (16 kHz mono int16 LE) instantly without a server round trip. Works only in a `play(useMelSpectrogram = true)` session.
- Added `RuntimeConfig.audioNonStreaming` — plays the speech audio at once after receiving all of it (default `true`). Dropouts caused by mid-speech buffer underruns disappear, at the cost of a longer delay before the first sound. Set it to `false` for the previous streaming playback.
- Server PCM→MEL live speech: consumes the PCM sent by the server as a single ordered stream and blocks leftover events from a previous session on reconnect via connection-generation (cid) guards.
- Unified session instrumentation: network and device state are recorded in New Relic through the single `SESSION_VITALS` event (line-speed measurement every 3 minutes, capped at 1.5 MB).

### Behavior Changes
- **Audio playback is now non-streaming by default.** The playback behavior changes simply by upgrading, with no API change. If you need the previous behavior, set `RuntimeConfig.audioNonStreaming = false`.
- Adding a default parameter to `play()` is **source-compatible but binary-incompatible**. Consumer apps must be recompiled (which happens automatically when the Gradle dependency is updated).

### Bug Fixes
- Blocked the race between interrupting speech (`sendStopSpeech`) and starting a new one — introduced a stop epoch, blocked audio re-queuing after interruption, and corrected the cleanup order.
- Double defense against stale messages and callbacks from a previous socket polluting the new session state on WebSocket reconnect. The connection-closed signal (Disconnected) is always delivered even when it arrives late.
- Fixed an issue where, after a disconnect and recovery during speech, the first utterance proceeded without `reset()`/`TTS_START` and mixed with leftover audio from the previous utterance.

## v0.11.0

**Release date**: July 2026

### New Features
- Added the `sessionId: String?` parameter to `chat()` — a multi-turn context key per conversation. Create a UUID when a conversation (visitor) starts, pass the same value to every `chat()` call in that conversation, and discard/regenerate it when the conversation ends (inactivity/standby). With `null`, the server responds without history as a one-off (backward compatible).
- Added the nullable `session_id` field to `ChatRequest`. The same `sessionId` is kept on 401 retries so conversation context is preserved.

## v0.10.1

## v0.10.0

**Release date**: June 2026

### Breaking Changes (STT SPI)
- Redefined the `SttProvider` contract: `startSession`/`endSession`/`release`/`onServerEvent` → `connect`/`disconnect`/`close`/`setEventSink`/`updateToken`.
- `SttProviderFactory`: `createDefault`/`getById` → `createDefaultOrNull`.
- Removed `SttServerEvent` and `VoiceServerBridge`; added `SttProviderEvent`, `SttSessionStatus`, `SttException`, and `SttTokenProvider`.
- Affects you only if you implemented a custom STT provider. No impact when using the bundled Azure provider.

### New Features
- `playRecoveryNotice()`: guidance speech while STT is recovering.
- `ResourceManager.loadRecoveryNotice()` / `copyRecoveryNotice()`.

### Improvements
- STT 24/7 stabilization: common `SttSessionSupervisor` refactor — concurrency stabilized with a single consumer (actor) + epoch guards, self-reconnect with backoff (30 s cap) for non-auth cancellations, separate handling of 403 authentication failures (APP_DISABLED/EXPIRED), and changeLanguage mailbox routing (ANR prevention).

## v0.8.0

**Release date**: May 2026

### Breaking Changes
- `KlleonOndeviceSdk.voiceRecognitionMode` default changed from `DISCRETE` to `ALWAYS_ON`. The microphone session starts automatically right after `play()`. To keep the DISCRETE flow, set `sdk.voiceRecognitionMode = VoiceRecognitionMode.DISCRETE` explicitly before calling `play()`.
- The `sttMode` default of `KlleonOndeviceSdk.play()` changed from `AUTO_SEND_TO_SERVER` to `STT_ONLY`. STT results are no longer sent to the server automatically; the app must call `sendMessage()` explicitly after receiving the `STT_RESULT` chat_type from `sdkState`. To keep automatic sending, specify `sttMode = SttMode.AUTO_SEND_TO_SERVER`.
- `startVoiceRecognition()` is `@Deprecated` — DISCRETE mode only. Use `startAlwaysOnListening()` instead. Scheduled for removal in v0.9.0+.
- `SttMode.AUTO_SEND_TO_SERVER` is `@Deprecated` — use `STT_ONLY` instead. Scheduled for removal in v0.9.0+.

### Migration
For detailed steps, see [Guides → v0.6.0 → v0.8.0 migration](/docs/guides/guides).

### Build Changes
- `sttProvider` default changed from `agora` to `azure` (Azure Direct STT recommended)
- Unified the debug `ATTEST_BASE_URL` to dev EKS (`https://dev.ondevice-biz.klleon.io`). When validating against an in-house LAN dev machine, temporarily swap it with the commented line in the build script.

## v0.7.0

**Release date**: May 2026

### Breaking Changes
- `AgoraSttProvider` is `@Deprecated` — Azure Direct STT is recommended. Agora Relay STT is scheduled for future removal.
- Removed `VoiceServerBridge.sendRecognizedText()` — the branch that sends STT results to the server was consolidated into `SttSessionManager`. There were no external callers (SDK-internal API).

### New Features
- **Introduced the `SttMode` enum** (`STT_ONLY` / `AUTO_SEND_TO_SERVER`) — a new parameter of `play()`. The default in this version is `AUTO_SEND_TO_SERVER` (changed to `STT_ONLY` in v0.8.0).
- **AppToken V2 attestation**: challenge-token → app-attest OkHttp flow → 24 h cache of `app_secret_key` (`SecureAttestStorage`). `AppToken.initialize()` is called automatically inside `ResourceManager.init()`.
- Added `ChatType.STT_AUTH_ERROR` / `SignalType.STT_AUTH_ERROR` — STT token V2 authentication failure (separated from `STT_ERROR`).
- Switched the model decryption key from V1 cert hash to the V2 `app_secret_key` (added `ServerKeyProvider`, removed `SignatureBasedKeyProvider`).

### Changes
- The `X-App-Secret-Key` header is used when fetching STT tokens, with one retry on 401 and immediate surfacing of 403.
