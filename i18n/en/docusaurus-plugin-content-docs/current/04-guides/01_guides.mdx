## v0.12.x → v0.13.0 Migration

> This release contains breaking changes.

### Summary of Changes

- Removed the `scope` parameter from `chat()` — the server dropped it from the contract
- Added `speech: CachedSpeechRef?` to `ChatBlock.Text` — **binary incompatible** (recompile required)

### 1. Audit every `chat()` call site ⚠️

:::danger Positional calls compile fine and fail silently
```kotlin
sdk.chat(ctx, text, "sony_booth", "ko")   // 0.12.x — compiles. "sony_booth" now binds to lang
sdk.chat(ctx, text, lang = "ko")          // 0.13.0
```
Only code that passed it as a named argument (`scope = ...`) will fail to compile. Code that
passed `scope` positionally will **request the wrong language without any error**, so grep for
`chat(` across your codebase.
:::

### 2. Recompile

The `copy`/`componentN` signatures of `ChatBlock.Text` changed. No source change is required,
but you must **rebuild** after upgrading the SDK.

### 3. (Optional) Switch to cached speech

If you were composing `speakCachedAsset()` calls yourself, you can move to `speakAnswer()` —
the SDK decides whether a cached recording exists and falls back to TTS or the notice audio.
See [7-1](#7-1-cached-speech).

## v0.6.0 → v0.8.0 Migration

> This release contains breaking changes. Follow the steps below to migrate.

### Summary of Changes
- `voiceRecognitionMode` default changed from `DISCRETE` to `ALWAYS_ON` (the microphone starts automatically right after `play()`)
- The `sttMode` default of `play()` changed from `AUTO_SEND_TO_SERVER` to `STT_ONLY` (STT results are no longer sent to the server automatically)
- `startVoiceRecognition()` is `@Deprecated` — use `startAlwaysOnListening()` instead
- `SttMode.AUTO_SEND_TO_SERVER` is `@Deprecated` — use `STT_ONLY` instead
- The `sttProvider` build default changed from `agora` to `azure`

### Migration Scenarios

#### Scenario A — Keep the previous behavior (fastest compatibility path)

```kotlin
// Before calling play()
sdk.voiceRecognitionMode = VoiceRecognitionMode.DISCRETE

// Specify sttMode explicitly when calling play()
@Suppress("DEPRECATION")
sdk.play(
    context, view, sdkKey, avatarId, language,
    sttMode = SttMode.AUTO_SEND_TO_SERVER,
)

// The microphone starts on a user action (deprecation warnings will appear)
@Suppress("DEPRECATION")
sdk.startVoiceRecognition()
```

→ Deprecation warnings appear, but the behavior is identical to v0.6.0. These APIs are scheduled for removal in v0.9.0+, so gradual migration is recommended.

#### Scenario B — Switch to ALWAYS_ON + STT_ONLY (recommended)

1. Remove the explicit `voiceRecognitionMode` / `sttMode` arguments (use the defaults)
2. Remove the microphone start/stop calls (`startVoiceRecognition` / `stopVoiceRecognition`) — the session starts automatically after `play()` and is kept until termination
3. Receive the `STT_RESULT` chat_type from `sdkState` → post-process it in your app logic → call `sdk.sendMessage(text)` explicitly

```kotlin
// ViewModel
viewModelScope.launch {
    sdk.sdkState.collect { json ->
        val chatType = JSONObject(json).optString("chat_type")
        val message = JSONObject(json).optString("message")
        if (chatType == "STT_RESULT" && message.isNotBlank()) {
            // Send explicitly after filtering/validation
            sdk.sendMessage(message)
        }
    }
}
```

#### Scenario C — Keep DISCRETE but disable automatic sending to the server

```kotlin
sdk.voiceRecognitionMode = VoiceRecognitionMode.DISCRETE
sdk.play(context, view, sdkKey, avatarId, language)  // sttMode omitted → STT_ONLY
@Suppress("DEPRECATION")
sdk.startVoiceRecognition()  // User push-to-talk action
```

### 1. Permission Management
- Always check permissions before initializing the SDK
- Handle permission denial with user-friendly messages
- Provide a clear rationale for the permissions you require
- Test the permission flow on various Android versions

```kotlin
private fun showPermissionRationale() {
    Toast.makeText(
        this,
        "This app requires audio permission to work properly.",
        Toast.LENGTH_LONG
    ).show()
}
```

### 2. Resource Management

Initialize resources with `ResourceManager.init()` and call `play()` only after the `onSuccess` callback.

#### Call Order

```
Select avatar   → ResourceManager.init(avatarId) → onSuccess → sdk.play() → ... → sdk.finish()
Same avatar     → ResourceManager.init(same avatarId) → buffers reused → immediate onSuccess → sdk.play()
Change avatar   → ResourceManager.init(new avatarId) → previous buffers released automatically + new allocation → onSuccess → sdk.play()
App termination → ResourceManager.deinit() (call it in Application.onDestroy or Activity.onDestroy)
```

#### Safe Cleanup Pattern

In Activities that use the SDK, call `finish()` from `onDestroy()`:

```kotlin
// ChatActivity (SDK playback screen)
override fun onDestroy() {
    super.onDestroy()
    // finish() is a suspend function, so run it from a coroutine
    CoroutineScope(Dispatchers.Default).launch {
        klleonOndeviceSdk.finish()
    }
}
```

If a screen only calls `init()` and `play()` is called from another Activity — like an avatar selection screen — release memory with `deinit()` when the SDK is not playing:

```kotlin
// CharacterActivity (avatar selection screen)
override fun onDestroy() {
    super.onDestroy()
    if (!KlleonOndeviceSdk.playing) {
        ResourceManager.deinit()
    }
}
```

#### Releasing Memory in the Background

When the app moves to the background, the ~1 GB YUV buffers are occupied unnecessarily. Register `ComponentCallbacks2` in your `Application` to release them automatically:

```kotlin
class MyApplication : Application() {
    override fun onCreate() {
        super.onCreate()
        registerComponentCallbacks(object : ComponentCallbacks2 {
            override fun onTrimMemory(level: Int) {
                if (level >= ComponentCallbacks2.TRIM_MEMORY_UI_HIDDEN) {
                    ResourceManager.deinit()
                }
            }
            override fun onConfigurationChanged(newConfig: Configuration) {}
            override fun onLowMemory() { ResourceManager.deinit() }
        })
    }
}
```

### 6. Speech Recognition Integration

Since v0.8.0, ALWAYS_ON + STT_ONLY is the default flow. Because the microphone session starts automatically after `play()`, your app only needs to receive and handle the STT events from `sdkState`.

```kotlin
// Results are received through the sdkState Flow
klleonOndeviceSdk.sdkState.collect { state ->
    val json = JSONObject(state)
    when (json.optString("chat_type")) {
        "STT_RESULT" -> {
            // Final speech recognition result — in the STT_ONLY flow the app calls sendMessage() explicitly
            val text = json.optString("message")
            if (text.isNotBlank()) {
                // Send after post-processing such as filtering/validation
                klleonOndeviceSdk.sendMessage(text)
            }
        }
        "STT_PARTIAL" -> {
            // Interim result (for real-time display)
            val partialText = json.optString("message")
        }
        "STT_STATUS" -> {
            val statusMessage = json.optString("message")
            showToast(statusMessage)
        }
        "STT_AUTH_ERROR" -> {
            // v0.7.0+ — STT token V2 attestation authentication failure
            showError("STT authentication failed: " + json.optString("message"))
        }
    }
}
```

### 7-1. Cached Speech

Plays a recording the server synthesized in advance, eliminating the TTS round trip.
Measured: **0.7 s** from STT to speech on a cache hit, versus 2.1–3.0 s via TTS.

#### Recommended — `speakAnswer()` (v0.13.0+)

Hand the chat response block to the SDK and it handles the routing and fallbacks.

```kotlin
CoroutineScope(Dispatchers.IO).launch {
    // Prerequisite: cached speech is enabled only when started in MEL mode
    klleonOndeviceSdk.play(
        context = this@Activity,
        klleonSdkViewInstance = sdkView,
        sdkKey = "YOUR_SDK_KEY",
        avatarId = "character_001",
        language = "ko_kr",
        useMelSpectrogram = true,
    )

    when (val result = klleonOndeviceSdk.chat(context, text = userInput, lang = "ko")) {
        is ChatResult.Success -> {
            // The first text block is the highest-scoring answer
            result.blocks.filterIsInstance<ChatBlock.Text>().firstOrNull()?.let { block ->
                klleonOndeviceSdk.speakAnswer(context, block)
                    .onSuccess { source -> Log.d(TAG, "Speech route: $source") }  // CACHED / TTS / ERROR_NOTICE
                    .onFailure { Log.e(TAG, "All speech paths failed: ${it.message}") }
            }
        }
        is ChatResult.Error -> Log.e(TAG, "${result.error}: ${result.message}")
    }
}
```

**Three-stage fallback** — prevents the case where the user speaks and hears nothing back.

| Stage | Condition | Result |
|---|---|---|
| 1 | Server returned `speech_file_name` **and the device holds it** | `CACHED` — local PCM playback |
| 2 | Otherwise, or playback failed | `TTS` — the existing server TTS |
| 3 | TTS also failed (socket dropped, etc.) | `ERROR_NOTICE` — local notice audio |

Stages 1 and 3 require a `useMelSpectrogram = true` session. Other sessions can only use
stage 2, and `Result.failure` is returned if that fails.

`ResourceManager.init()` synchronizes the cache with the server automatically. If the server
holds no assets, the sync completes with zero downloads and every answer goes through stage 2 —
this is not a failure.

#### Low level — `speakCachedAsset()` (v0.12.0+)

Use this to play a fixed line directly, without going through chat.

```kotlin
if (klleonOndeviceSdk.isCachedSpeechReady()) {
    klleonOndeviceSdk.speakCachedAsset("greeting_ko.pcm")
        .onFailure { Log.w(TAG, "Cached speech failed: ${it.message}") }
}
```

- The audio format is fixed to **16 kHz mono int16 little-endian PCM**.
- Calling it in a `play(useMelSpectrogram = false)` session returns `Result.failure(IllegalStateException)` — check with `isCachedSpeechReady()` first.
- Calling `sendStopSpeech()` during cached speech interrupts it immediately, just like server speech.

### 7-2. Audio Playback Mode (v0.12.0+)

```kotlin
RuntimeConfig.audioNonStreaming = true   // Default — buffer the speech, then play it at once
RuntimeConfig.audioNonStreaming = false  // Streaming — play as chunks arrive
```

| Mode | Delay to first sound | Mid-speech dropouts | Recommended for |
|------|------------|----------|----------|
| Non-streaming (default) | Long | None | General environments, poor networks |
| Streaming | Short | Possible on slow networks | Stable networks where low latency matters |

The value is captured when speech starts and stays fixed until that utterance ends.

### 9. Standby Mode

Like a computer screensaver, this feature switches the avatar to a standby state after a period of inactivity and returns from it with a wake word.

#### Flow

```
play() → setIdleTimeout() → conversation → TTS_END → 60 seconds of inactivity
  → STANDBY_ENTER event → automatic enterStandby()
  → wake word detected → exitStandby() + language switch → conversation resumes

When the server never responds after a message is sent (v0.12.1+)
sendMessage() → response watchdog (up to 20 s, within the 60 s budget) → no server event
  → the remaining 40 s continues to count as inactivity → STANDBY_ENTER
  ※ The total wait is always timeoutMs (60 s), whether or not a message was sent
```

#### Configuring Automatic Standby

```kotlin
// Enable the idle timeout after calling play()
klleonOndeviceSdk.play(context, view, sdkKey, avatarId, language)
klleonOndeviceSdk.setIdleTimeout(60_000L)  // Automatic standby after 60 seconds of inactivity
```

If you don't call it, the automatic standby feature stays disabled.

#### Exiting Standby with a Wake Word

Combined with wakeword matching, standby can be exited by voice command. Wakeword matching is enabled automatically on `enterStandby()` and disabled automatically on `exitStandby()`, so no separate on/off control is needed in the app.

```kotlin
// Register wakewords (for language switching) — registration alone does not enable matching
klleonOndeviceSdk.registerWakewords(mapOf(
    "ジャパニーズ" to "ja_jp",
    "イングリッシュ" to "en_us",
    "コリアン" to "ko_kr",
))

// Switch language and exit standby when a wakeword is detected
// Because matching only runs during standby, wakewordDetected emits only in the standby state
klleonOndeviceSdk.wakewordDetected.collect { result ->
    klleonOndeviceSdk.sendChangeLanguage(result.tag)
    if (klleonOndeviceSdk.isStandby()) {
        klleonOndeviceSdk.exitStandby()  // Matching is disabled automatically as well
    }
}
```

:::tip
Place `sendChangeLanguage()` outside the `isStandby()` guard. Under the current policy wakewords match only during standby, but keeping it outside the guard is better defensive coding.
:::

:::caution
Wake-word detection works only while STT is active. Use `VoiceRecognitionMode.ALWAYS_ON`. In `DISCRETE` mode you must exit standby by another means, such as touch or a button.
:::

#### Receiving the STANDBY_ENTER Event

When automatic standby is entered, a `STANDBY_ENTER` event is published through `sdkState`. Your app can use it for UI updates such as showing an overlay.

```kotlin
klleonOndeviceSdk.sdkState.collect { state ->
    if (state.contains("STANDBY_ENTER")) {
        // Show the standby UI
    }
}
```

## Troubleshooting

### Common Problems

#### 1. Permission Denied
**Problem**: The `RECORD_AUDIO` permission is not granted

**Solution**:
- Check that the permission is declared in `AndroidManifest.xml`
- Review your permission handling logic
- Test on various Android versions

#### 2. SDK State Is Not Updating
**Problem**: State observation is not working

**Solution**:
- Verify that state observation is set up correctly in the ViewModel
- Verify that the coroutine scope is active
- Verify that state collection has started

#### 3. View Is Not Ready
**Problem**: `KlleonSdkView` is not initialized before `play()` is called

**Solution**:
- Verify view initialization in the `AndroidView` factory
- Enable the button only when the view is ready
- Add a null check before calling SDK methods

#### 4. USB Microphone Is Not Recognized
**Problem**: A USB microphone is connected but the SDK does not use it

**Solution**:
- Check the connection state with `hasUsbMicrophone()`
- The MMAP policy is managed internally by the SDK (default: disabled). Some USB microphones are not MMAP-compatible
- Check the device logs: `adb logcat | grep "Ondevice_Mic"`

#### 5. Speech Recognition Does Not Work While the Avatar Is Speaking
**Problem**: Speech recognition does not start while the avatar is talking

**Solution**:
- Speech recognition is blocked while the avatar is speaking to prevent echo
- Interrupt the avatar first with `sendStopSpeech()`, or try again after the speech finishes

### Debugging Tips

#### Monitoring State
```kotlin
// Monitor all state changes
klleonOndeviceSdk.sdkState.collect { state ->
    Log.d("SDKState", "State update: $state")

    try {
        val json = JSONObject(state)
        val message = json.getString("message")
        val chatType = json.optString("chat_type", "unknown")
        Log.d("SDKState", "Parsed - chatType: $chatType, message: $message")
    } catch (e: Exception) {
        Log.w("SDKState", "Failed to parse state JSON", e)
    }
}
```

#### Monitoring Recorder State
```kotlin
// Monitor recorder state changes
klleonOndeviceSdk.recorderState.collect { state ->
    when (state) {
        is OboeRecorderState.Recording -> {
            Log.d("Recorder", "Recording - device: ${state.deviceName}")
        }
        is OboeRecorderState.Error -> {
            Log.e("Recorder", "Error: ${state.message}")
        }
        else -> Log.d("Recorder", "State: $state")
    }
}
```
