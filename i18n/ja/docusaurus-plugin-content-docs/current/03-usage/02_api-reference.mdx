# API リファレンス

## 主要コンポーネント

### KlleonOndeviceSdk

すべての機能を提供するメインの SDK クラスです。

```kotlin
// シングルトンで管理します（推奨）
object SdkConfig {
    val sdk = KlleonOndeviceSdk()
}
val klleonOndeviceSdk = SdkConfig.sdk
```

### KlleonSdkView

SDK のコンテンツをレンダリングするためのカスタム Android View です。

```kotlin
@Composable
fun SdkViewComponent() {
    var workerView by remember { mutableStateOf<KlleonSdkView?>(null) }

    AndroidView(
        factory = { context ->
            KlleonSdkView(context).also { view ->
                workerView = view
            }
        },
        modifier = Modifier.fillMaxSize()
    )
}
```

#### setRenderRotation()

TV などで画面回転が必要な場合に使用します。

```kotlin
klleonSdkView.setRenderRotation(270) // 0, 90, 270 度に対応
```

## ResourceManager

リソースの初期化と解放を担当するクラスです。`play()` の前に必ず `init()` でリソースを準備する必要があります。

```kotlin
val resourceManager = ResourceManager()
```

### init()

アバターのリソースをキャッシュディレクトリへコピーし、YUV 変換とネイティブメモリへの読み込みを行います。

```kotlin
resourceManager.init(
    context: Context,
    mp4FileName: String,
    npzFileName: String,
    styleFileName: String = "",
    faceCropYuvFileName: String = "",
    faceCropYuvMetaFileName: String = "",
    avatarId: String = "",
    onSuccess: () -> Unit,
    onError: (Throwable) -> Unit
)
```

**パラメータ:**
| パラメータ | 型 | 必須 | 説明 |
|---------|------|------|------|
| `context` | Context | O | 現在のコンテキスト |
| `mp4FileName` | String | O | アバターの MP4 ファイル名（assets 内） |
| `npzFileName` | String | O | アバターの NPZ ファイル名（assets 内） |
| `styleFileName` | String | X | スタイルファイル名（デフォルト: ""） |
| `faceCropYuvFileName` | String | X | 事前抽出された face crop YUV のファイル名（デフォルト: ""）。指定すると `warpAffine` の工程をスキップし、推論経路を短縮します（LIPSYNC-007, v0.6.0） |
| `faceCropYuvMetaFileName` | String | X | face crop YUV のメタファイル名（デフォルト: ""）。`faceCropYuvFileName` と併用します |
| `avatarId` | String | X | アバター ID。同一アバターへの再入時はバッファを再利用し、即座に `onSuccess` を返します |
| `onSuccess` | () -> Unit | O | リソース準備完了のコールバック |
| `onError` | (Throwable) -> Unit | O | エラーコールバック |

**例:**
```kotlin
resourceManager.init(
    context = this,
    mp4FileName = "loop_sample.mp4",
    npzFileName = "loop_sample.npz",
    styleFileName = "loop_sample.style",
    avatarId = "character_001",
    onSuccess = {
        // 準備完了 — play() は suspend のためコルーチンから呼び出します
        CoroutineScope(Dispatchers.IO).launch {
            klleonOndeviceSdk.play(context, sdkView, sdkKey, avatarId, language)
        }
    },
    onError = { error ->
        Log.e("SDK", "リソースの準備に失敗しました", error)
    }
)
```

:::info バッファの再利用
同一のアバター（`avatarId`）で `init()` を再度呼び出すと、準備済みのバッファを再利用して即座に `onSuccess` を返します。別のアバターに切り替える場合は、以前のバッファを解放して新規に確保します。
:::

### deinit()

ネイティブの YUV バッファメモリを解放し、リソースの状態を初期化します。

```kotlin
resourceManager.deinit()
```

:::tip 冪等性の保証
`deinit()` は複数回呼び出しても安全です。すでに解放済みの状態で呼び出した場合は no-op です。
:::

### 呼び出し規約

1. **`init()`** — アバターの選択完了時に呼び出します。アバター変更時は以前のバッファを自動的に解放します。
2. **`play()`** — `init()` の `onSuccess` コールバックが来た場合にのみ呼び出せます
3. **`deinit()`** — アプリの完全終了時に呼び出します。`finish()` はバッファを保持し、同一アバターへの再入を最適化します。

## SDK メソッド

### play()

AI アバターのビデオ再生を開始します。`suspend` 関数のため、コルーチン内から呼び出す必要があります。

v0.7.0+ で `sttMode` パラメータを追加、v0.8.0+ でデフォルトを `STT_ONLY` に変更、v0.12.0+ で `useMelSpectrogram` パラメータを追加しました。

```kotlin
suspend fun play(
    context: Context,
    klleonSdkViewInstance: KlleonSdkView?,
    sdkKey: String,
    avatarId: String,
    language: String,
    sttMode: SttMode = SttMode.STT_ONLY,
    useMelSpectrogram: Boolean = false,
)
```

**パラメータ:**
| パラメータ | 型 | 必須 | 説明 |
|---------|------|------|------|
| `context` | Context | O | 現在のコンテキスト |
| `klleonSdkViewInstance` | KlleonSdkView? | O | レンダリングビュー |
| `sdkKey` | String | O | SDK 認証キー |
| `avatarId` | String | O | AI アバター ID |
| `language` | String | O | 言語コード（`ko_kr`, `en_us`, `ja_jp`） |
| `sttMode` | [SttMode](#sttmode) | X | STT 結果の通知モード（デフォルト `STT_ONLY` — 結果の受信後にアプリが `sendMessage()` を明示的に呼び出します） |
| `useMelSpectrogram` | Boolean | X | リップシンクのパイプラインモード（v0.12.0+、デフォルト `false`）。`true` の場合は MEL スペクトログラム経路で起動し、[キャッシュ発話 API](#キャッシュ発話-api) を利用できます |

`voiceRecognitionMode` が `ALWAYS_ON`（v0.8.0+ のデフォルト）の場合、`play()` の後にマイクセッションが自動的に開始されます。別途 `startAlwaysOnListening()` を呼び出す必要はありません。

**例:**
```kotlin
CoroutineScope(Dispatchers.IO).launch {
    workerView?.let { view ->
        klleonOndeviceSdk.play(
            context = this@Activity,
            klleonSdkViewInstance = view,
            sdkKey = "YOUR_SDK_KEY",
            avatarId = "character_001",
            language = "ko_kr",
            // sttMode = SttMode.STT_ONLY,  // v0.8.0+ のデフォルト（省略可）
        )
    }
}
```

### connect()

WebSocket の再接続を行います。

```kotlin
klleonOndeviceSdk.connect()
```

### finish()

SDK を停止し、すべてのリソースを解放します。`suspend` 関数のため、コルーチン内から呼び出す必要があります。
内部バッファは、同一アバターへの再入時に再利用するため保持されます（soft reset）。

```kotlin
// Activity 終了時
CoroutineScope(Dispatchers.Default).launch {
    klleonOndeviceSdk.finish()
}
```

### awaitFinish()

進行中の `finish()` が完了するまで待機します。終了処理中でなければ即座に戻ります。
`finish()` の直後に `play()` を再度呼び出す場合は、`ResourceManager.init()` の前に呼び出してリソース競合を防ぎます。

```kotlin
// 高速な再入時
CoroutineScope(Dispatchers.Default).launch {
    klleonOndeviceSdk.awaitFinish()  // 前回の終了完了を待機します
    ResourceManager.init(context, ...)
}
```

## メッセージ API

### sendMessage()

SDK のメッセージングシステムを通じてメッセージを送信します。

```kotlin
klleonOndeviceSdk.sendMessage(text: String)
```

**例:**
```kotlin
klleonOndeviceSdk.sendMessage("こんにちは")
```

### sendMessageEcho()

入力テキストをそのまま TTS + リップシンクで再生します（LLM をバイパス）。固定の案内文などに使用します。

```kotlin
klleonOndeviceSdk.sendMessageEcho(text: String)
```

### sendChangeLanguage()

会話中に言語を動的に変更します。

```kotlin
klleonOndeviceSdk.sendChangeLanguage(language: String)
```

**例:**
```kotlin
// 英語に変更します
klleonOndeviceSdk.sendChangeLanguage("en")
```

### sendStopSpeech()

アバターの現在の発話を即座に中断します。

```kotlin
klleonOndeviceSdk.sendStopSpeech()
```

## Chat API

biz-backend `/api/v1/chat` を呼び出します。HTTP・認証・画像 URL の絶対化・パースは SDK が処理し、呼び出し側は blocks のみを受け取ります。raw app secret key は SDK 内部に閉じ込められます。

### chat()

```kotlin
suspend fun chat(
    context: Context,
    text: String,
    lang: String = "ko",
    sessionId: String? = null,
): ChatResult
```

| パラメータ | 型 | 必須 | 説明 |
|---------|------|------|------|
| `text` | String | O | ユーザー入力 |
| `lang` | String | X | 応答言語（`ko` / `en` / `ja`） |
| `sessionId` | String? | X | 会話単位のマルチターン文脈キー。会話開始時に UUID を生成してその会話のすべての呼び出しで再利用し、終了時に破棄します。`null` の場合、サーバーは履歴なしの単発で応答します |

`play()` セッションは不要で、`ResourceManager.init()` の先行のみ必要です。結果は `ChatResult.Success(blocks)` または `ChatResult.Error(error, message)` で、`ChatBlock` は `Text` / `Image` / `Unknown` です（未知の type は `Unknown` にフォールバックし、前方互換性を保証します）。

### ChatBlock.Text.speech

v0.13.0+。テキスト block に **サーバーのキャッシュ音声への参照** が含まれる場合があります。

```kotlin
data class Text(
    val content: String,
    val speech: CachedSpeechRef? = null,
) : ChatBlock()

data class CachedSpeechRef(
    val fileName: String,   // 例: "Mn38h2DpWyJ2.pcm"
    val format: String?,    // 例: "pcm_s16le_16k"
)
```

`speech` が `null` でない場合、**サーバーにこの回答の録音がある** という意味です。再生せよという指示ではなく、端末がそのファイルを取得済みかを確認するための **参照キー** です。存在しない場合は通常どおり TTS で発話してください。

```kotlin
val ref = block.speech
if (ref != null && myCache.has(ref.fileName)) {
    klleonOndeviceSdk.speakCachedPcm16Le(myCache.read(ref.fileName))
} else {
    klleonOndeviceSdk.sendMessageEcho(block.content)   // TTS フォールバック
}
```

:::info
`fileName` は回答テキストの決定的なハッシュです。**自前で計算せず、サーバーが返した値をそのまま参照キーとして使用してください** — ハッシュ規則を複製すると静かにずれます。`format` は補助情報であり、判定キーは `fileName` の 1 つだけです。
:::

### setChatBaseUrl()

v0.13.0+。[chat()](#chat) リクエストの送信先サーバーを変更します。ローカル・ステージングサーバーの検証用です。

```kotlin
fun setChatBaseUrl(url: String?)
```

`null` を渡すと SDK のデフォルトに戻ります。起動時のキャッシュ音声同期も指定サーバーを参照させるため、`ResourceManager.init()` の **前に** 呼び出してください。

## キャッシュ発話 API

v0.12.0+。あらかじめ用意した PCM オーディオをサーバー往復なしで即座に発話します。挨拶や案内文のような固定のセリフで応答遅延をなくす用途に使用します。

**前提**: `play(useMelSpectrogram = true)` で起動したセッションでのみ動作します。それ以外のセッションで呼び出すと `Result.failure(IllegalStateException)` を返します。

### speakCachedAsset()

アプリの assets 内の PCM ファイルを発話します。

```kotlin
suspend fun speakCachedAsset(assetName: String): Result<Int>
```

| パラメータ | 型 | 必須 | 説明 |
|---------|------|------|------|
| `assetName` | String | O | assets 内の PCM ファイル名（16kHz モノラル int16 LE） |

戻り値は発話に使用したサンプル数です。失敗時は `Result.failure` を返します。

### speakCachedPcm16Le()

メモリ上の PCM バイト列を発話します。

```kotlin
suspend fun speakCachedPcm16Le(pcmBytes: ByteArray): Result<Int>
```

| パラメータ | 型 | 必須 | 説明 |
|---------|------|------|------|
| `pcmBytes` | ByteArray | O | 16kHz モノラル int16 リトルエンディアン PCM（キャッシュ仕様により 16kHz 固定） |

### キャッシュストア（v0.13.0+）

SDK がキャッシュ PCM を保管し、保持しているかどうかを返します。`chat()` レスポンスの [speech](#chatblocktextspeech) が **サーバーにあるか** を伝えるのに対し、こちらは **この端末にあるか** に答えます。ファイルはアプリ専用の内部ストレージに保管され、他のアプリからはアクセスできません。

```kotlin
fun hasCachedSpeech(context: Context, fileName: String): Boolean
fun importCachedSpeech(context: Context, fileName: String, pcmBytes: ByteArray): Boolean
fun cachedSpeechCount(context: Context): Int
suspend fun speakCachedFile(fileName: String): Result<Int>
```

| 関数 | 説明 | `play()` 必要 |
|------|------|------|
| `hasCachedSpeech` | 保持しているか。毎回の応答で呼び出せるようメモリ参照です | X |
| `importCachedSpeech` | 格納。16kHz モノラル int16 LE の raw PCM。同名は上書きします | X |
| `cachedSpeechCount` | 保持件数（診断用） | X |
| `speakCachedFile` | 保持しているファイル名で発話 | **O**（`useMelSpectrogram = true`） |

### speakAnswer()

v0.13.0+。**2 段階の判定とフォールバックを SDK が代行します。** 上記の関数を自分で組み合わせる代わりに、こちらを使ってください。

```kotlin
suspend fun speakAnswer(context: Context, block: ChatBlock.Text): Result<SpeechSource>

enum class SpeechSource { CACHED, TTS, ERROR_NOTICE }
```

| 段階 | 条件 | 結果 |
|---|---|---|
| 1 | サーバーがキャッシュファイル名を返し、かつ端末が保持している | `CACHED` — ローカル PCM、サーバー往復なし |
| 2 | それ以外、またはキャッシュ再生に失敗 | `TTS` — 従来の WebSocket 発話 |
| 3 | TTS も失敗（WebSocket 切断など） | `ERROR_NOTICE` — 案内音声のみ。**回答は伝わりません** |

```kotlin
val first = blocks.filterIsInstance<ChatBlock.Text>().firstOrNull()
first?.let { block ->
    when (klleonOndeviceSdk.speakAnswer(context, block).getOrNull()) {
        SpeechSource.CACHED -> { /* キャッシュヒット */ }
        SpeechSource.TTS -> { /* 通常経路 */ }
        SpeechSource.ERROR_NOTICE -> { /* 回答が伝わっていない — 画面表示などの追加対応を検討 */ }
        null -> { /* 案内音声すら失敗 */ }
    }
}
```

:::info
3 段階目がある理由は **沈黙を防ぐため** です。ユーザーが話しかけたのに何の音も出ないと、アバターが無視したように見えます。

1 段と 3 段は `play(useMelSpectrogram = true)` のセッションでのみ動作します。それ以外のセッションでは 2 段のみ利用可能で、失敗時は `Result.failure` です。
:::

**自分で組み合わせる場合**（`speakAnswer` を使わないとき）:
```kotlin
val ref = block.speech                                            // 1 次 — サーバーにあるか
if (ref != null && sdk.hasCachedSpeech(context, ref.fileName)) {  // 2 次 — 端末にあるか
    sdk.speakCachedFile(ref.fileName)                             // ローカル PCM 発話
} else {
    sdk.sendMessageEcho(block.content)                            // TTS フォールバック
}
```

### syncCachedSpeech()

v0.13.0+。サーバーのキャッシュ音声一覧と端末の保持分を突き合わせます — ないものや更新されたものだけをダウンロードし、サーバーから消えたものは削除します。アプリ起動時など任意のタイミングで呼び出してください。`play()` セッションは不要です。

```kotlin
suspend fun syncCachedSpeech(
    context: Context,
    onProgress: ((done: Int, total: Int) -> Unit)? = null,
): Result<CachedSpeechSyncResult>

data class CachedSpeechSyncResult(
    val remoteTotal: Int, val downloaded: Int, val removed: Int, val failed: Int,
)
```

```kotlin
scope.launch {
    klleonOndeviceSdk.syncCachedSpeech(context) { done, total ->
        updateProgress(done, total)
    }.onSuccess { Log.i(TAG, "同期: $it") }
}
```

:::info
**[setChatBaseUrl](#setchatbaseurl) で指定したサーバーから取得します。** ファイル名は `chat()` レスポンス由来のため、アセットも同じサーバーでなければ名前が一致しません。

再ダウンロードの判定はサーバーの `updated_at` で行います — ファイル名は回答テキストのハッシュであり、同じ文を録音し直しても名前が変わらないためです。

中断しても安全です（サーバーはステートレス）。再度呼び出すと残りから再開します。すでに同期が実行中の場合は即座に失敗を返します。個々のファイルの失敗は `failed` として数え、**全体を中断しません**。
:::

:::info
`importCachedSpeech` はファイル名にパス区切りや `..` が含まれる場合は拒否します。`updatedAt` を併せて渡すと、次回の同期でそのファイルを最新として扱います（省略するとバージョン不明とみなし、一度だけ再取得します）。

保持一覧にあってもファイルが消えている場合、`speakCachedFile` は失敗を返し、一覧から自動的に削除します。その際は TTS にフォールバックしてください — `hasCachedSpeech` が true でも発話が保証されるわけではありません。
:::

### isCachedSpeechReady()

キャッシュ発話が利用可能な状態かを確認します。

```kotlin
fun isCachedSpeechReady(): Boolean
```

**例:**
```kotlin
CoroutineScope(Dispatchers.IO).launch {
    klleonOndeviceSdk.play(
        context = this@Activity,
        klleonSdkViewInstance = view,
        sdkKey = "YOUR_SDK_KEY",
        avatarId = "character_001",
        language = "ko_kr",
        useMelSpectrogram = true,          // キャッシュ発話の前提
    )

    if (klleonOndeviceSdk.isCachedSpeechReady()) {
        klleonOndeviceSdk.speakCachedAsset("greeting_ko.pcm")
            .onFailure { Log.w(TAG, "キャッシュ発話に失敗しました: ${it.message}") }
    }
}
```

## ランタイム設定（RuntimeConfig）

v0.12.0+。再生中でも変更できる SDK の動作トグルです。

### audioNonStreaming

```kotlin
RuntimeConfig.audioNonStreaming = true   // デフォルト
```

- `true`（デフォルト）: **ノンストリーミング** — 1 つの発話のオーディオを最後まで受信してから一括再生します。途中のバッファアンダーランによる途切れがなくなる一方、最初の音までの遅延は長くなります。
- `false`: **ストリーミング** — サーバーのオーディオチャンクを到着した順に再生します。低遅延ですが、低速回線ではアンダーランにより発話が途切れ途切れになることがあります。

値は **発話開始時点で取得** され、その発話が終わるまで固定されます（発話中に切り替えてもモードが混在しません）。

> v0.12.0 からデフォルトはノンストリーミングです。以前のバージョンの再生動作が必要な場合は `false` を設定してください。

## Wakeword API

STT の認識結果から登録済みの wakeword を検出し、コールバックを通知します。Wakeword がマッチした場合、その STT 結果は通常の会話入力（`STT_RESULT`）から除外されます。

:::note Standby 連携のポリシー
Wakeword マッチングはデフォルトで **無効** です。`enterStandby()` の呼び出し時に自動的に有効化され、`exitStandby()` の呼び出し時に自動的に無効化されます。`registerWakewords()` で wakeword を登録しても、standby モードに入らないとマッチングは動作しません。
:::

:::info STT の言語と wakeword
`play(language)` または `sendChangeLanguage(language)` で設定した言語が、STT の認識言語としても適用されます。Wakeword マッチングはその言語の STT 認識結果に対して動作するため、**各言語の STT が認識できる wakeword を登録** する必要があります。

例:
- 韓国語 STT → `"영어"`、`"일본어"`、`"니혼고"` などの韓国語発音の wakeword
- 日本語 STT → `"韓国語"`、`"英語"`、`"コリアン"` などの日本語で認識される wakeword
- 英語 STT → `"Korean"`、`"Japanese"` などの英語の wakeword
:::

### registerWakewords()

Wakeword を登録します。既存の wakeword はすべて置き換えられます。登録するだけではマッチングは動作せず、`enterStandby()` への進入時に有効化されます。

```kotlin
fun registerWakewords(wakewords: Map<String, String>)
```

**パラメータ:**
| パラメータ | 型 | 説明 |
|---------|------|------|
| `wakewords` | Map\<String, String\> | wakeword → タグのマップ。Wakeword が検出されると、タグの値がコールバックで通知されます |

**例:**
```kotlin
// 言語切り替え用の wakeword を登録します
klleonOndeviceSdk.registerWakewords(mapOf(
    "니혼고" to "ja_jp", "일본어" to "ja_jp",
    "잉글리쉬" to "en_us", "영어" to "en_us",
    "한국어" to "ko_kr", "코리안" to "ko_kr",
))
```

### clearWakewords()

登録済みの wakeword をすべて初期化します。初期化後は wakeword マッチングが動作せず、すべての STT 結果が `STT_RESULT` として通知されます。

```kotlin
klleonOndeviceSdk.clearWakewords()
```

### wakewordDetected

Wakeword のマッチング結果を emit する `SharedFlow` です。

```kotlin
val wakewordDetected: SharedFlow<WakewordResult>
```

**WakewordResult:**
| フィールド | 型 | 説明 |
|------|------|------|
| `wakeword` | String | マッチした wakeword の原文（例: `"니혼고"`） |
| `tag` | String | 登録時に指定したタグ（例: `"ja_jp"`） |
| `fullText` | String | STT が認識した全文 |

**例:**
```kotlin
// Wakeword 検出時に言語を切り替えます
LaunchedEffect(Unit) {
    klleonOndeviceSdk.wakewordDetected.collect { result ->
        // result.wakeword = "니혼고", result.tag = "ja_jp"
        klleonOndeviceSdk.sendChangeLanguage(result.tag)
    }
}
```

:::tip
SDK は wakeword が何を意味するかには関与しません。タグの値はアプリ側で自由に定義でき、言語コード以外にも `"mode_quiet"`、`"stop"` など任意の文字列を使用できます。
:::

## 待機画面（Standby）API

### enterStandby()

待機画面モードに入ります。パイプライン全体を整理（キューの排出、オーディオバッファの破棄、タイミングの初期化）したうえで、ビデオデコードとオーディオ再生を一時停止します。リソースは保持されます。

```kotlin
klleonOndeviceSdk.enterStandby()
```

### exitStandby()

待機画面モードを解除します。ビデオデコードとオーディオ再生を再開します。

```kotlin
klleonOndeviceSdk.exitStandby()
```

### isStandby()

待機画面モードの状態かどうかを確認します。

```kotlin
val isStandby: Boolean = klleonOndeviceSdk.isStandby()
```

### setIdleTimeout(timeoutMs)

idle timeout を有効化します。アバターの発話終了（TTS_END）後、指定時間の無操作が続くと自動的に `enterStandby()` を呼び出します。`STANDBY_ENTER` イベントが `sdkState` から発行された後、待機画面に入ります。

```kotlin
// デフォルトは 60 秒
klleonOndeviceSdk.setIdleTimeout()

// カスタム timeout（30 秒）
klleonOndeviceSdk.setIdleTimeout(30_000L)
```

:::info
`play()` の呼び出し前後のいずれのタイミングでも呼び出せます。呼び出さない場合、自動待機画面機能は無効のままです。
:::

### disableIdleTimeout()

idle timeout を無効化します。有効なタイマーがある場合はキャンセルされます。

```kotlin
klleonOndeviceSdk.disableIdleTimeout()
```

### avatarState: StateFlow\<AvatarState\>

v0.10.3 から提供されます。アバターの発話ライフサイクル状態を型付き Flow として公開します。汎用的な `sdkState` 文字列ストリームから発話状態のみを分離した値です。

```kotlin
enum class AvatarState {
    IDLE,       // 待機
    PREPARING,  // 応答準備中
    SPEAKING,   // 発話中
}
```

```kotlin
klleonOndeviceSdk.avatarState.collect { state ->
    when (state) {
        AvatarState.IDLE -> { /* 待機 UI */ }
        AvatarState.PREPARING -> { /* 応答準備中の表示 */ }
        AvatarState.SPEAKING -> { /* 発話中の表示 */ }
    }
}
```

### isResponding: StateFlow\<Boolean\>

アバターが応答準備中または発話中であれば `true` です。v0.10.3 からは `avatarState != IDLE` の派生値です（つまり `PREPARING` または `SPEAKING` のとき `true`、`IDLE` のとき `false`）。boolean としての動作は従来どおりです。

```kotlin
// 現在の値を確認します
if (klleonOndeviceSdk.isResponding.value) {
    // アバターが応答中です
}

// Flow で購読します
klleonOndeviceSdk.isResponding.collect { responding ->
    // UI を更新します
}
```

## 音声認識 API

v0.8.0 から `voiceRecognitionMode` のデフォルトは `ALWAYS_ON`、`sttMode` のデフォルトは `STT_ONLY` です。`play()` 直後にマイクセッションが自動開始され、STT の結果は `sdkState` の `STT_RESULT` chat_type で通知されます — アプリが後処理を行ってから `sendMessage()` を呼び出すフローです。

| API | モード | 動作 | 用途 |
|---|---|---|---|
| `startAlwaysOnListening` ⭐ | `ALWAYS_ON` | VAD/ゲーティングなしでセッションを維持し、すべての音声を STT へ送信します | 常時リスニング、連続会話（推奨） |
| `startVoiceRecognition` ⚠️ Deprecated | `DISCRETE` | VAD が無音を検出すると自動終了します（1 発話単位） | プッシュトゥトーク、単発コマンド — v0.9.0 以降で削除予定 |

### SttMode

STT 認識結果の通知モードを表す enum です（v0.7.0+）。`play()` の時点で設定します。

```kotlin
enum class SttMode {
    /** STT のみ使用（デフォルト、v0.8.0+） — 結果をアプリ UI にのみ返します。サーバー LLM へは送信しません。 */
    STT_ONLY,

    /** STT の結果を即座にサーバーへ送信します — アプリ UI + サーバー LLM。 */
    @Deprecated("v0.9.0 以降で削除予定です。STT_ONLY + sendMessage() の明示呼び出しを推奨します。")
    AUTO_SEND_TO_SERVER,
}
```

用途:
- **STT_ONLY**（デフォルト）: アプリが `sdkState` の `STT_RESULT` chat_type を受信 → フィルタリング/検証 → `sendMessage()` を明示的に呼び出します。
- **AUTO_SEND_TO_SERVER**（Deprecated）: ユーザーの発話 → 即座に AI 応答（従来のフローと互換）。

### voiceRecognitionMode

音声認識モードを設定します。`play()` の呼び出し前に設定する必要があります。

```kotlin
// v0.8.0+ のデフォルトが ALWAYS_ON のため、通常は呼び出し不要です
klleonOndeviceSdk.voiceRecognitionMode = VoiceRecognitionMode.ALWAYS_ON
```

**モード:**
| モード | 説明 |
|------|------|
| `ALWAYS_ON` | 常時リスニング（v0.8.0+ のデフォルト）。`play()` 後に自動開始し、セッションを維持します |
| `DISCRETE` | 単発モード。`startVoiceRecognition()` で手動により開始/終了します（Deprecated なフロー） |

### startAlwaysOnListening()

ALWAYS_ON リスニングを開始します。`voiceRecognitionMode = ALWAYS_ON` の場合は `play()` の内部で自動的に呼び出されるため、通常は外部から直接呼び出す必要はありません。権限拒否後の再許可のような特殊なフローでのみ明示的に呼び出してください。

```kotlin
val success: Boolean = klleonOndeviceSdk.startAlwaysOnListening()
```

### isAutoListening()

ALWAYS_ON の自動リスニング中かどうかを確認します。

```kotlin
val isListening: Boolean = klleonOndeviceSdk.isAutoListening()
```

### startVoiceRecognition()

⚠️ **Deprecated（v0.8.0+）** — `startAlwaysOnListening()` の使用を推奨します。v0.9.0 以降で削除予定です。

DISCRETE モードの音声認識を開始します。マイク録音を開始し、WebSocket で START_VOICE シグナルを送信します。無音が検出されると自動的に録音を終了し、END_VOICE シグナルを送信します。

```kotlin
@Deprecated("DISCRETE モードの音声認識は v0.9.0 以降で削除予定です")
fun startVoiceRecognition(
    config: SilenceDetectionConfig = SilenceDetectionConfig.default()
): Boolean
```

**パラメータ:**
- `config`: 無音検出の設定（任意、デフォルト: `SilenceDetectionConfig.default()`）

**戻り値:** 成功可否（Boolean）

呼び出し前に `sdk.voiceRecognitionMode = VoiceRecognitionMode.DISCRETE` の明示が必要です（v0.8.0+ のデフォルトが ALWAYS_ON のため）。

### stopVoiceRecognition()

音声認識を停止します。DISCRETE モードのフローにおける手動終了に使用します。

```kotlin
klleonOndeviceSdk.stopVoiceRecognition()
```

### isVoiceRecognizing()

音声認識中かどうかを確認します。

```kotlin
val isRecognizing: Boolean = klleonOndeviceSdk.isVoiceRecognizing()
```

## 状態管理

### sdkState

SDK の状態更新を JSON 文字列として emit する SharedFlow です。

```kotlin
klleonOndeviceSdk.sdkState: SharedFlow<String>
```

**使い方:**
```kotlin
klleonOndeviceSdk.sdkState.collect { state ->
    val messageToAdd = try {
        val json = JSONObject(state)
        json.getString("message")
    } catch (t: Throwable) {
        state.toString()
    }

    // 状態更新の処理
    updateUI(messageToAdd)
}
```

**状態のフォーマット（JSON）:**
```json
{
  "message": "",
  "chat_type": "ACTIVATE_VOICE",
  "time": "2025-09-03T05:42:08.394975295",
  "id": "99dd3ab3-53c4-4418-bee4-b1fbaea272aa"
}
```

**主な chat_type の値:**
| chat_type | 説明 |
|-----------|------|
| `WSS_OPEN` | WebSocket 接続成功 |
| `WSS_FAILURE` | WebSocket 接続失敗 |
| `WSS_CLOSING` | WebSocket 接続終了中 |
| `WSS_CLOSED` | WebSocket 接続終了 |
| `WSS_RETRY_OVER` | 最大リトライ回数超過 |
| `WSS_NOT_CONNECTED` | 未接続状態 |
| `ACTIVATE_VOICE` | 音声入力の受信準備完了 |
| `TEXT` | サーバーからのテキスト応答を受信 |
| `RESPONSE_IS_ENDED` | サーバー応答ストリームの終了 |
| `TTS_START` | TTS 音声の再生開始 |
| `TTS_END` | TTS 音声の再生完了（発話終了の検出に使用） |
| `SHOW_AVATAR` | アバターの表示準備完了 |
| `USER_SPEECH_STARTED` | ユーザーの発話開始を検出 |
| `USER_SPEECH_STOPPED` | ユーザーの発話終了を検出 |
| `PREPARING_RESPONSE` | サーバーが応答を準備中 |
| `STT_RESULT` | 音声認識の最終結果 |
| `STT_PARTIAL` | 音声認識の中間結果 |
| `STT_ERROR` | 音声認識のエラー |
| `STT_STATUS` | 音声認識の状態変化通知（準備中/再接続中/準備完了） |
| `WORKER_DISCONNECTED` | ソケット接続の終了 |
| `SPEECH_START` | アバターの発話開始 |
| `SPEECH_END` | アバターの発話終了 |
| `STOP_RESPONSE_MESSAGE` | 現在のアバター発話を中断 |

#### STT_STATUS の詳細

音声認識セッションの一時的な状態変化を通知します。トークンベース認証を使用する STT プロバイダ（Azure など）で発生します。

| 状態 | message の値 | 意味 | 発生タイミング |
|------|------------|------|-----------|
| `Preparing` | `음성 인식 준비 중` | トークン待ちのため認識開始が遅延しています | トークン未受信の状態で音声認識を開始したとき |
| `Recovering` | `음성 인식 재연결 중` | 認証失敗によりトークンの再発行を待っています | 認識中に認証トークンが期限切れになったとき |
| `Ready` | `음성 인식 준비 완료` | 復旧完了、音声認識を再開しました | トークン再発行後に認識を再開したとき |

:::tip
`STT_STATUS` は一時的な状態通知です。`음성 인식 준비 중` または `음성 인식 재연결 중` を受信した際にトースト等でユーザーへ案内し、`음성 인식 준비 완료` の受信時に自然に解除するとよいでしょう。
:::

## SilenceDetectionConfig

音声認識時の無音検出動作を設定します。

```kotlin
import io.klleon.ondevice.audio.oboe.SilenceDetectionConfig
```

**フィールド:**
| フィールド | 型 | デフォルト | 説明 |
|------|------|--------|------|
| `silenceThreshold` | Float | 0.02 | 無音と判定するレベルのしきい値 |
| `speechThreshold` | Float | 0.05 | 音声と判定するレベルのしきい値 |
| `speechTimeoutMs` | Long | 5000 | 音声入力の待機時間（ms） |
| `silenceTimeoutMs` | Long | 2000 | 音声後の無音検出時間（ms） |
| `maxRecordingTimeMs` | Long | 60000 | 最大録音時間（ms、0 = 無制限） |
| `preBufferMs` | Int | 300 | 音声開始前のオーディオ保持時間（ms） |
| `preBufferDelayMs` | Long | 300 | プリバッファのフラッシュ遅延（ms） |

**プリセット:**
| プリセット | 特徴 |
|--------|------|
| `SilenceDetectionConfig.default()` | 標準設定 |
| `SilenceDetectionConfig.fast()` | 高速応答（speechTimeout 3 秒、silenceTimeout 1.5 秒） |
| `SilenceDetectionConfig.longSpeech()` | 長い発話（speechTimeout 7 秒、silenceTimeout 3 秒、maxRecording 120 秒） |
| `SilenceDetectionConfig.noisyEnvironment()` | 騒音環境（しきい値を引き上げ: silence 0.05、speech 0.10） |

**例:**
```kotlin
// プリセットの使用
klleonOndeviceSdk.startVoiceRecognition(SilenceDetectionConfig.fast())

// カスタム設定
val config = SilenceDetectionConfig.default().copy(
    speechTimeoutMs = 3000L,
    maxRecordingTimeMs = 120_000L
)
klleonOndeviceSdk.startVoiceRecognition(config)
```

## ライフサイクル管理

`play()` と `finish()` は `suspend` 関数です。Activity のライフサイクルではコルーチンでラップして呼び出します。

```kotlin
class ChatActivity : ComponentActivity() {
    private val sdk = SdkConfig.sdk

    override fun onDestroy() {
        super.onDestroy()
        // finish() は suspend のためコルーチンで実行します
        CoroutineScope(Dispatchers.Default).launch {
            sdk.finish()  // SDK を停止します（バッファは再利用のため保持）
        }
        ResourceManager.deinit()  // アプリの完全終了時にのみ呼び出します
    }
}
```

### 高速な再入（finish → play）

`finish()` の直後に `play()` を呼び出すと、リソース競合が発生することがあります。
`awaitFinish()` を使用して、前回の終了完了後に進めてください。

```kotlin
// キャラクター選択画面で新しいアバターを開始する場合
CoroutineScope(Dispatchers.Default).launch {
    sdk.awaitFinish()  // 前回の finish() が進行中であれば完了を待機します
    ResourceManager.init(context, mp4, npz, style, avatarId,
        onSuccess = { /* ChatActivity を開始 → play() */ },
        onError = { /* エラー処理 */ }
    )
}
```
