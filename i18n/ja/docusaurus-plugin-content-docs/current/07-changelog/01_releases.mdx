## v0.12.0 (Latest)

**リリース日**: 2026 年 8 月

### 新機能
- `play()` に `useMelSpectrogram: Boolean = false` パラメータを追加しました — MEL スペクトログラムベースのリップシンクパイプラインへ切り替えるモードスイッチです。`false`（デフォルト）は従来の AUDIO_FEATURE 経路のままです。
- キャッシュ発話 API を追加しました: `speakCachedAsset(assetName: String): Result<Int>`、`speakCachedPcm16Le(pcmBytes: ByteArray): Result<Int>`、`isCachedSpeechReady(): Boolean`。あらかじめ用意した PCM（16kHz モノラル int16 LE）をサーバー往復なしで即座に発話します。`play(useMelSpectrogram = true)` のセッションでのみ動作します。
- `RuntimeConfig.audioNonStreaming` を追加しました — 発話オーディオを最後まで受信してから一括再生します（デフォルト `true`）。途中のバッファアンダーランによる途切れがなくなる一方、最初の音までの遅延は長くなります。`false` にすると従来のストリーミング再生になります。
- サーバー PCM→MEL のライブ発話: サーバーが送信した PCM を単一の ordered ストリームとして消費し、接続世代（cid）ベースのガードにより再接続時に前セッションの残存イベントを遮断します。
- セッション計測の統合: `SESSION_VITALS` の単一イベントでネットワーク・デバイスの状態を New Relic に記録します（回線速度測定は 3 分周期、1.5MB 上限）。

### 動作変更
- **オーディオ再生がノンストリーミングのデフォルト** になりました。API の変更なしに、アップグレードするだけで再生方式が変わります。従来の動作が必要な場合は `RuntimeConfig.audioNonStreaming = false` を設定してください。
- `play()` へのデフォルトパラメータ追加は **ソース互換ですがバイナリ非互換** です。利用側アプリの再コンパイルが必要です（Gradle の依存関係更新時に自動的に行われます）。

### バグ修正
- 発話中断（`sendStopSpeech`）と新規発話の開始が重なる際の競合を遮断しました — stop epoch の導入、中断後のオーディオ再投入の遮断、クリーンアップ順序の修正を行いました。
- WebSocket 再接続時に、以前のソケットの stale メッセージ・コールバックが新しいセッションの状態を汚染する問題を二重に防御しました。接続終了シグナル（Disconnected）は遅延到着でも必ず通知されます。
- 発話中に接続が切断され復旧した際、最初の発話が `reset()`/`TTS_START` なしで進行し、前の発話の残存オーディオと混ざる問題を修正しました。

## v0.11.0

**リリース日**: 2026 年 7 月

### 新機能
- `chat()` に `sessionId: String?` パラメータを追加しました — 会話単位のマルチターン文脈キーです。1 つの会話（来訪者）の開始時に UUID を生成し、その会話のすべての `chat()` 呼び出しに同じ値を渡し、会話終了（無操作/standby）時に破棄・再生成します。`null` の場合、サーバーは履歴なしの単発として応答します（後方互換）。
- `ChatRequest` に nullable な `session_id` フィールドを追加しました。401 リトライ時も同じ `sessionId` を維持し、会話の文脈を保持します。

## v0.8.0

**リリース日**: 2026 年 5 月

### Breaking Changes
- `KlleonOndeviceSdk.voiceRecognitionMode` のデフォルトが `DISCRETE` → `ALWAYS_ON` になりました。`play()` 直後にマイクセッションが自動開始されます。DISCRETE のフローを維持する場合は、`play()` の呼び出し前に `sdk.voiceRecognitionMode = VoiceRecognitionMode.DISCRETE` を明示してください。
- `KlleonOndeviceSdk.play()` の `sttMode` デフォルトが `AUTO_SEND_TO_SERVER` → `STT_ONLY` になりました。STT の結果はサーバーへ自動送信されず、アプリが `sdkState` の `STT_RESULT` chat_type を受信したうえで `sendMessage()` を明示的に呼び出す必要があります。自動送信を維持する場合は `sttMode = SttMode.AUTO_SEND_TO_SERVER` を明示してください。
- `startVoiceRecognition()` は `@Deprecated` — DISCRETE モード専用です。`startAlwaysOnListening()` の使用を推奨します。v0.9.0 以降で削除予定です。
- `SttMode.AUTO_SEND_TO_SERVER` は `@Deprecated` — `STT_ONLY` の使用を推奨します。v0.9.0 以降で削除予定です。

### マイグレーション
詳細な手順は [ガイド → v0.6.0 → v0.8.0 マイグレーション](/category/04-guides) を参照してください。

### ビルドの変更
- `sttProvider` のデフォルトが `agora` → `azure` になりました（Azure Direct STT を推奨）
- debug の `ATTEST_BASE_URL` を dev EKS（`https://dev.ondevice-biz.klleon.io`）に統一しました。社内 LAN の dev マシンで検証する場合は、ビルドスクリプト内のコメント行と一時的に差し替えてください。

## v0.7.0

**リリース日**: 2026 年 5 月

### Breaking Changes
- `AgoraSttProvider` は `@Deprecated` — Azure Direct STT を推奨します。Agora Relay STT は将来的に削除予定です。
- `VoiceServerBridge.sendRecognizedText()` を削除しました — STT 結果のサーバー送信分岐は `SttSessionManager` に統合されました。外部からの呼び出し元はありませんでした（SDK 内部 API）。

### 新機能
- **`SttMode` enum の導入**（`STT_ONLY` / `AUTO_SEND_TO_SERVER`） — `play()` の新規パラメータです。本バージョンのデフォルトは `AUTO_SEND_TO_SERVER` です（v0.8.0 で `STT_ONLY` に変更）。
- **AppToken V2 attestation**: challenge-token → app-attest の OkHttp フロー → `app_secret_key` の 24 時間キャッシュ（`SecureAttestStorage`）。`ResourceManager.init()` の内部で `AppToken.initialize()` が自動的に呼び出されます。
- `ChatType.STT_AUTH_ERROR` / `SignalType.STT_AUTH_ERROR` を新設しました — STT トークン V2 の認証失敗（`STT_ERROR` から分離）。
- モデル復号鍵を V1 の cert hash から V2 の `app_secret_key` へ移行しました（`ServerKeyProvider` を新設、`SignatureBasedKeyProvider` を削除）。

### 変更点
- STT トークン取得時に `X-App-Secret-Key` ヘッダーを使用し、401 では 1 回リトライ、403 は即座に surface します。

## v0.5.0

**リリース日**: 2026 年 4 月

### Breaking Changes
- `pauseVideo()` / `resumeVideo()` / `isVideoPaused()` を `enterStandby()` / `exitStandby()` / `isStandby()` にリネームしました
- `registerKeywords()` / `clearKeywords()` / `keywordDetected` を `registerWakewords()` / `clearWakewords()` / `wakewordDetected` にリネームしました

### 新機能
- 待機画面（Standby）モード: パイプライン全体の flush + タイミング再初期化により早送り/ANR を防止します
- ウェイクワードマッチング: STT の認識結果から登録済みキーワードを検出し、コールバックを通知します（standby 中のみ有効）
- `setIdleTimeout()` / `disableIdleTimeout()`: TTS_END 後の無操作で自動的に待機画面へ入ります
- `isResponding: StateFlow<Boolean>`: アバターの応答状態を追跡します（PREPARING_RESPONSE 〜 TTS_END）
- `STANDBY_ENTER` イベント: 自動待機画面への進入時に sdkState から発行されます

### バグ修正
- VideoDecoder `stop()` の競合状態（pauseToken/stopToken の順序逆転）
- ASYNC モードの consumer が pauseToken を確認していなかった問題
- AudioPlayer に `pause()` / `resume()` を追加（ビデオのみ停止しオーディオが再生され続ける問題の修正）
