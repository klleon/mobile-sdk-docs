# 既知の制限事項

SDK を使用する前に、以下の要件と制限事項をご確認ください。

## デバイス要件

| 項目 | OpenCL 最小 | OpenCL 推奨 |
|------|-------------|-------------|
| **Android バージョン** | 8.0（API 26） | 12+（API 31） |
| **RAM** | 4GB | 6GB 以上 |
| **ストレージ** | 500MB | 1GB 以上 |
| **GPU** | OpenGL ES 2.0 / OpenCL 1.2 | OpenGL ES 3.0+ / OpenCL 2.0+ |

## 対応アーキテクチャ（ABI）

| ABI | 対応状況 | 備考 |
|-----|----------|------|
| `arm64-v8a` | 対応 | ほとんどの最新デバイス |
| `armeabi-v7a` | 対応 | 旧型の 32bit デバイス |
| `x86_64` | 非対応 | エミュレータ |
| `x86` | 非対応 | エミュレータ |

:::warning エミュレータに関する注意
x86/x86_64 エミュレータでは SDK は動作しません。

**テスト方法:**
- 実機の Android デバイスを使用する（推奨）
- ARM ベースのエミュレータを使用する（例: Apple Silicon Mac の標準エミュレータ）
:::

## ネットワーク要件

### 必須条件
- **インターネット接続**: リアルタイム WebSocket 通信に必須です
- **プロトコル**: HTTPS / WSS（TLS 1.2 以上）
- **ポート**: 443

### ファイアウォール設定
```

```

### ネットワーク権限
```xml

<uses-permission android:name="android.permission.ACCESS_NETWORK_STATE" />
```

## オーディオ関連の制限事項

### USB マイクの互換性

- **MMAP ポリシー**: MMAP は SDK 内部で管理され、デフォルトでは無効です。MMAP を有効にすると、一部の USB マイクでストリームのオープンに失敗することがあります。
- **USB デバイスの選択**: USB マイクが接続されると自動的に検出され選択されます。
- **非互換デバイス**: 一部の MediaTek ベースの TV では、USB 複合デバイス（例: DM30RGB）のオーディオストリームのオープンに失敗することがあります。

### エコー防止
- アバターの発話中は音声認識が自動的に遮断されます。

### 再生モードのトレードオフ（v0.12.0+）
- デフォルトは **ノンストリーミング**（`RuntimeConfig.audioNonStreaming = true`）です。発話オーディオを最後まで受信してから再生するため、途中の途切れはなくなりますが、**最初の音が出るまでの遅延が長くなります**。
- 低遅延が必要な場合は `false` に設定しますが、低速回線ではバッファアンダーランにより発話が途中で終了（途切れ途切れになる）することがあります。
- 値は発話開始時点で取得されるため、発話中に切り替えてもその発話には反映されません。

### キャッシュ発話の制約（v0.12.0+）
- `play(useMelSpectrogram = true)` で起動したセッションでのみ動作します。それ以外では `Result.failure(IllegalStateException)` を返します。
- オーディオ形式は **16kHz モノラル int16 リトルエンディアン PCM** に固定です（キャッシュ仕様）。他のサンプルレートには対応していません。
- キャッシュ発話とサーバー発話は同時に再生されません。一方が進行中の場合、もう一方は待機するか中断されます。

## 既知の問題

### 1. メモリ使用量

ビデオ処理および AI 推論中はメモリ使用量が高くなることがあります。特に `ResourceManager.init()` の呼び出し時に、YUV フレームバッファとして **約 1GB のネイティブメモリ** が確保されます。

#### バッファのライフサイクル

`finish()` はバッファを保持するため、同一アバターへの再入時に即座に再利用できます（0ms）。完全なメモリ解放には `deinit()` の明示的な呼び出しが必要です。

| シナリオ | 動作 |
|----------|------|
| 同一アバターへの再入 | `init(同一 avatarId)` → バッファを再利用（0ms） |
| 別アバターへの切り替え | `init(新しい avatarId)` → 以前のバッファを自動解放 + 新規確保 |
| アプリのバックグラウンド遷移 | `onTrimMemory` → `deinit()` → バッファ解放 |
| アプリ終了 | `CharacterActivity.onDestroy` → `deinit()` → 完全解放 |
| プロセスの強制終了 | OS カーネルが自動回収（コード不要） |

#### 必須の実装パターン

**Application クラス — バックグラウンドでのメモリ自動解放:**
```kotlin
class MyApplication : Application() {
    override fun onCreate() {
        super.onCreate()
        registerComponentCallbacks(object : ComponentCallbacks2 {
            override fun onTrimMemory(level: Int) {
                if (level >= ComponentCallbacks2.TRIM_MEMORY_UI_HIDDEN) {
                    ResourceManager.deinit()
                }
            }
            override fun onConfigurationChanged(newConfig: Configuration) {}
            override fun onLowMemory() { ResourceManager.deinit() }
        })
    }
}
```

**SDK 再生画面（ChatActivity など）:**
```kotlin
override fun onDestroy() {
    super.onDestroy()
    // finish() は suspend 関数のためコルーチンで実行します
    CoroutineScope(Dispatchers.Default).launch {
        klleonOndeviceSdk.finish() // バッファを保持（再利用待ち）
    }
}
```

**アバター選択画面（CharacterActivity など）:**
```kotlin
override fun onDestroy() {
    super.onDestroy()
    // SDK が再生中でない場合（play 前に離脱）は手動でメモリを解放します
    if (!KlleonOndeviceSdk.playing) {
        ResourceManager.deinit()
    }
}
```

:::info 重複呼び出しに対する安全性
- `init()`: 同一アバター（`avatarId`）で再度呼び出した場合は既存バッファを再利用します（重複確保なし）
- `deinit()`: 複数回呼び出しても安全です（冪等性を保証）
- `finish()`: 内部の playing 状態チェックにより重複呼び出しでも安全です
:::

### 2. バックグラウンドの制限

アプリがバックグラウンドに移行すると、ビデオ処理は一時停止します。


### 3. 単一インスタンスの制限

`KlleonOndeviceSdk` のインスタンスは **アプリごとに 1 つだけ** 生成してください。
内部のコルーチンスコープとスレッドプールはインスタンスごとに確保されるため、複数のインスタンスを生成するとリソース競合やメモリリークが発生します。

**推奨: object シングルトンで管理する**

```kotlin
// アプリ全体で単一インスタンスを共有します
object SdkConfig {
    val sdk = KlleonOndeviceSdk()
}

// Activity での使用
class ChatActivity : ComponentActivity() {
    private val klleonOndeviceSdk = SdkConfig.sdk  // 同一インスタンスを再利用
}

class AnotherActivity : ComponentActivity() {
    private val klleonOndeviceSdk = SdkConfig.sdk  // 同一インスタンスを再利用
}
```

:::caution 注意
Activity のフィールドで `KlleonOndeviceSdk()` を直接生成すると、Activity の再生成（画面回転、メモリ不足など）のたびに新しいインスタンスが作られ、以前のインスタンスのスレッドプールが蓄積します。
:::

```kotlin
// 誤った使い方 - 複数インスタンス
class MainActivity : Activity() {
    val sdk1 = KlleonOndeviceSdk() // インスタンス 1
    val sdk2 = KlleonOndeviceSdk() // インスタンス 2 - 競合が発生します！
}
```

### 4. 画面回転

画面回転で Activity が再生成されると、SDK の状態が初期化されることがあります。

**対処方法:**
```xml
<!-- AndroidManifest.xml - 画面回転を自前で処理します -->
<activity
    android:name=".MainActivity"
    android:configChanges="orientation|screenSize|screenLayout" />
```

### 5. Android TV 固有の注意点

- TV プラットフォームではレイアウト変更時に最初の focusable 要素へ自動的にフォーカスが移り、キーボードが自動表示されることがあります。
- `focusProperties { canFocus = false }` で根本的に遮断し、クリック時のみ有効化してください。
- MediaTek ベースの TV では一部の USB オーディオデバイスに互換性の問題が発生することがあります。

## パフォーマンス最適化のヒント

### GPU アクセラレーション

SDK はデフォルトで GPU アクセラレーションを使用します。一部の低スペックデバイスで問題が発生した場合は次を確認してください。

```kotlin
// GPU の問題が発生した際のログ確認
adb logcat | grep "Klleon_"
```

### バッテリー最適化

長時間使用するとバッテリー消費が大きくなることがあります。
- 使用しないときは `finish()` を呼び出してください
- 画面消灯時は処理を停止することを推奨します
- `enterStandby()` / `exitStandby()` で待機画面モードを活用してください
