## v0.6.0 → v0.8.0 마이그레이션

> 본 릴리스에 Breaking 변경이 포함되어 있습니다. 아래 단계를 따라 마이그레이션하세요.

### 변경 요약
- `voiceRecognitionMode` 기본값 `DISCRETE` → `ALWAYS_ON` (`play()` 직후 마이크 자동 시작)
- `play()` 의 `sttMode` 기본값 `AUTO_SEND_TO_SERVER` → `STT_ONLY` (STT 결과의 서버 자동 전송 X)
- `startVoiceRecognition()` `@Deprecated` — `startAlwaysOnListening()` 권장
- `SttMode.AUTO_SEND_TO_SERVER` `@Deprecated` — `STT_ONLY` 권장
- `sttProvider` 빌드 기본값 `agora` → `azure`

### 마이그레이션 시나리오

#### 시나리오 A — 이전 동작 그대로 유지 (가장 빠른 호환 경로)

```kotlin
// play() 호출 전
sdk.voiceRecognitionMode = VoiceRecognitionMode.DISCRETE

// play() 호출 시 sttMode 명시
@Suppress("DEPRECATION")
sdk.play(
    context, view, sdkKey, avatarId, language,
    sttMode = SttMode.AUTO_SEND_TO_SERVER,
)

// 마이크는 사용자 액션으로 시작 (Deprecated 경고 발생)
@Suppress("DEPRECATION")
sdk.startVoiceRecognition()
```

→ Deprecated 경고가 발생하지만 동작은 v0.6.0 과 동일. v0.9.0+ 에서 제거 예정이므로 점진적 마이그레이션 권장.

#### 시나리오 B — ALWAYS_ON + STT_ONLY 로 전환 (권장)

1. `voiceRecognitionMode` / `sttMode` 인자 명시 제거 (기본값 사용)
2. 마이크 시작/정지 호출 (`startVoiceRecognition` / `stopVoiceRecognition`) 제거 — `play()` 후 자동 시작, 종료까지 세션 유지
3. `sdkState` 의 `STT_RESULT` chat_type 수신 → 앱 로직에서 후처리 → `sdk.sendMessage(text)` 명시 호출

```kotlin
// ViewModel
viewModelScope.launch {
    sdk.sdkState.collect { json ->
        val chatType = JSONObject(json).optString("chat_type")
        val message = JSONObject(json).optString("message")
        if (chatType == "STT_RESULT" && message.isNotBlank()) {
            // 필터/검수 후 명시 전송
            sdk.sendMessage(message)
        }
    }
}
```

#### 시나리오 C — DISCRETE 유지하면서 서버 자동 전송만 끄기

```kotlin
sdk.voiceRecognitionMode = VoiceRecognitionMode.DISCRETE
sdk.play(context, view, sdkKey, avatarId, language)  // sttMode 생략 → STT_ONLY
@Suppress("DEPRECATION")
sdk.startVoiceRecognition()  // 사용자 PTT 동작
```

### 2. 리소스 관리

`ResourceManager.init()`으로 리소스를 초기화하고, `onSuccess` 콜백 후에만 `play()`를 호출하세요.

#### 호출 순서

```
아바타 선택   → ResourceManager.init(avatarId) → onSuccess → sdk.play() → ... → sdk.finish()
같은 아바타   → ResourceManager.init(동일 avatarId) → 버퍼 재사용 → 즉시 onSuccess → sdk.play()
아바타 변경   → ResourceManager.init(새 avatarId) → 자동으로 이전 버퍼 해제 + 새 할당 → onSuccess → sdk.play()
앱 종료      → ResourceManager.deinit() (Application.onDestroy 또는 Activity.onDestroy에서 호출)
```

#### 안전한 정리 패턴

SDK를 사용하는 Activity에서는 `onDestroy()`에서 `finish()`를 호출하세요:

```kotlin
// ChatActivity (SDK play 화면)
override fun onDestroy() {
    super.onDestroy()
    // finish()는 suspend 함수이므로 코루틴에서 실행
    CoroutineScope(Dispatchers.Default).launch {
        klleonOndeviceSdk.finish()
    }
}
```

아바타 선택 화면처럼 `init()`만 호출하고 `play()`는 다른 Activity에서 호출하는 경우,
SDK가 재생 중이 아니면 `deinit()`으로 메모리를 해제하세요:

```kotlin
// CharacterActivity (아바타 선택 화면)
override fun onDestroy() {
    super.onDestroy()
    if (!KlleonOndeviceSdk.playing) {
        ResourceManager.deinit()
    }
}
```

#### 백그라운드 메모리 해제

앱이 백그라운드로 전환되면 ~1GB YUV 버퍼가 불필요하게 점유됩니다. `Application`에 `ComponentCallbacks2`를 등록하여 자동 해제하세요:

```kotlin
class MyApplication : Application() {
    override fun onCreate() {
        super.onCreate()
        registerComponentCallbacks(object : ComponentCallbacks2 {
            override fun onTrimMemory(level: Int) {
                if (level >= ComponentCallbacks2.TRIM_MEMORY_UI_HIDDEN) {
                    ResourceManager.deinit()
                }
            }
            override fun onConfigurationChanged(newConfig: Configuration) {}
            override fun onLowMemory() { ResourceManager.deinit() }
        })
    }
}
```

### 6. 음성 인식 통합

v0.8.0 부터 ALWAYS_ON + STT_ONLY 가 기본 흐름입니다. `play()` 후 마이크 세션이 자동 시작되므로, 앱은 `sdkState` 의 STT 이벤트만 수신·처리하면 됩니다.

```kotlin
// 결과는 sdkState Flow로 수신
klleonOndeviceSdk.sdkState.collect { state ->
    val json = JSONObject(state)
    when (json.optString("chat_type")) {
        "STT_RESULT" -> {
            // 음성 인식 최종 결과 — STT_ONLY 흐름에서는 앱이 sendMessage() 명시 호출
            val text = json.optString("message")
            if (text.isNotBlank()) {
                // 필터/검수 등 후처리 후 전송
                klleonOndeviceSdk.sendMessage(text)
            }
        }
        "STT_PARTIAL" -> {
            // 중간 결과 (실시간 표시용)
            val partialText = json.optString("message")
        }
        "STT_STATUS" -> {
            val statusMessage = json.optString("message")
            showToast(statusMessage)
        }
        "STT_AUTH_ERROR" -> {
            // v0.7.0+ — STT 토큰 V2 attestation 인증 실패
            showError("STT 인증 실패: " + json.optString("message"))
        }
    }
}
```

### 7. 발화 중단

아바타가 발화 중일 때 즉시 중단할 수 있습니다.

```kotlin
klleonOndeviceSdk.sendStopSpeech()
```

### 7-1. 캐시 발화 (v0.12.0+)

인사말·안내 문구처럼 **고정된 대사**는 미리 준비한 PCM으로 발화해 서버 왕복 지연을 없앨 수 있습니다.

```kotlin
CoroutineScope(Dispatchers.IO).launch {
    // 전제: MEL 모드로 기동해야 캐시 발화가 활성화된다
    klleonOndeviceSdk.play(
        context = this@Activity,
        klleonSdkViewInstance = sdkView,
        sdkKey = "YOUR_SDK_KEY",
        avatarId = "character_001",
        language = "ko_kr",
        useMelSpectrogram = true,
    )

    if (klleonOndeviceSdk.isCachedSpeechReady()) {
        klleonOndeviceSdk.speakCachedAsset("greeting_ko.pcm")
            .onFailure { Log.w(TAG, "캐시 발화 실패: ${it.message}") }
    }
}
```

- 오디오 포맷은 **16kHz mono int16 little-endian PCM** 고정입니다.
- `play(useMelSpectrogram = false)` 세션에서 호출하면 `Result.failure(IllegalStateException)` 을 반환합니다 — `isCachedSpeechReady()` 로 먼저 확인하세요.
- 캐시 발화 중 `sendStopSpeech()` 를 호출하면 서버 발화와 동일하게 즉시 중단됩니다.

### 7-2. 오디오 재생 모드 (v0.12.0+)

```kotlin
RuntimeConfig.audioNonStreaming = true   // 기본값 — 발화를 완충 후 일괄 재생
RuntimeConfig.audioNonStreaming = false  // 스트리밍 — 도착하는 대로 재생
```

| 모드 | 첫 소리 지연 | 중간 끊김 | 권장 상황 |
|------|------------|----------|----------|
| 논스트리밍(기본) | 길다 | 없음 | 일반 환경, 열악한 회선 |
| 스트리밍 | 짧다 | 느린 망에서 발생 가능 | 저지연이 중요한 안정적 회선 |

값은 발화 시작 시점에 캡처되어 그 발화가 끝날 때까지 고정됩니다.

### 9. 대기화면(Standby) 모드

컴퓨터의 화면보호기처럼, 일정 시간 무활동 시 아바타를 대기 상태로 전환하고 wake-word로 복귀하는 기능입니다.

#### 흐름

```
play() → setIdleTimeout() → 대화 → TTS_END → 60초 무활동
  → STANDBY_ENTER 이벤트 → 자동 enterStandby()
  → wake-word 감지 → exitStandby() + 언어 전환 → 대화 재개
```

#### 자동 대기화면 설정

```kotlin
// play() 호출 후 idle timeout 활성화
klleonOndeviceSdk.play(context, view, sdkKey, avatarId, language)
klleonOndeviceSdk.setIdleTimeout(60_000L)  // 60초 무활동 시 자동 대기
```

호출하지 않으면 자동 대기화면 기능은 비활성화됩니다.

#### Wake-word로 대기화면 해제

Wakeword 매칭과 결합하여 음성 명령으로 대기화면을 해제할 수 있습니다. Wakeword 매칭은 `enterStandby()` 시 자동으로 활성화되고 `exitStandby()` 시 자동으로 비활성화되므로, 앱에서 별도의 on/off 제어가 필요 없습니다.

```kotlin
// Wakeword 등록 (언어 전환용) — 등록만으로는 매칭 비활성
klleonOndeviceSdk.registerWakewords(mapOf(
    "ジャパニーズ" to "ja_jp",
    "イングリッシュ" to "en_us",
    "コリアン" to "ko_kr",
))

// Wakeword 감지 시 언어 전환 + standby 해제
// standby 중에만 매칭이 동작하므로 wakewordDetected는 standby 상태에서만 emit됨
klleonOndeviceSdk.wakewordDetected.collect { result ->
    klleonOndeviceSdk.sendChangeLanguage(result.tag)
    if (klleonOndeviceSdk.isStandby()) {
        klleonOndeviceSdk.exitStandby()  // 매칭도 자동 비활성화
    }
}
```

:::tip
`sendChangeLanguage()`는 `isStandby()` guard 밖에 배치하세요. 현재 정책에서는 standby 중에만 wakeword가 매칭되지만, 방어적 코딩을 위해 guard 밖에 두는 것이 좋습니다.
:::

:::caution
wake-word 감지는 STT가 활성 상태일 때만 동작합니다. `VoiceRecognitionMode.ALWAYS_ON` 모드를 사용하세요. `DISCRETE` 모드에서는 터치/버튼 등 별도 방법으로 해제해야 합니다.
:::

#### STANDBY_ENTER 이벤트 수신

자동 대기화면 진입 시 `sdkState`로 `STANDBY_ENTER` 이벤트가 발행됩니다. 앱에서 UI 업데이트(오버레이 표시 등)에 활용할 수 있습니다.

```kotlin
klleonOndeviceSdk.sdkState.collect { state ->
    if (state.contains("STANDBY_ENTER")) {
        // 대기화면 UI 표시
    }
}
```

## 문제 해결

### 일반적인 문제

#### 1. 권한 거부됨
**문제**: `RECORD_AUDIO` 권한이 허용되지 않음

**해결책**:
- `AndroidManifest.xml`에 권한이 선언되어 있는지 확인
- 권한 처리 로직 확인
- 다양한 Android 버전에서 테스트

#### 2. SDK 상태가 업데이트되지 않음
**문제**: 상태 관찰이 작동하지 않음

**해결책**:
- ViewModel에서 상태 관찰이 제대로 설정되어 있는지 확인
- 코루틴 스코프가 활성화되어 있는지 확인
- 상태 수집이 시작되었는지 확인

#### 3. 뷰가 준비되지 않음
**문제**: `play()` 호출 전에 `KlleonSdkView`가 초기화되지 않음

**해결책**:
- `AndroidView` 팩토리에서 뷰 초기화 확인
- 뷰가 준비되었을 때만 버튼 활성화
- SDK 메서드 호출 전에 null 검사 추가

#### 4. USB 마이크가 인식되지 않음
**문제**: USB 마이크를 연결했으나 SDK에서 사용하지 않음

**해결책**:
- `hasUsbMicrophone()`으로 연결 상태 확인
- MMAP 정책은 SDK 내부에서 관리됩니다 (기본: 비활성화). 일부 USB 마이크는 MMAP 비호환
- 디바이스 로그 확인: `adb logcat | grep "Ondevice_Mic"`

#### 5. 아바타 발화 중 음성 인식 안 됨
**문제**: 아바타가 말하는 동안 음성 인식이 시작되지 않음

**해결책**:
- 에코 방지를 위해 아바타 발화 중에는 음성 인식이 차단됩니다
- `sendStopSpeech()`로 아바타 발화를 먼저 중단하거나, 발화 완료 후 시도하세요

klleonOndeviceSdk.sdkState.collect { state ->
