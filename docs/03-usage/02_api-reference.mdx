# API 참조

## 핵심 컴포넌트

### KlleonOndeviceSdk

모든 기능을 제공하는 메인 SDK 클래스입니다.

```kotlin
// 싱글톤으로 관리 (권장)
object SdkConfig {
    val sdk = KlleonOndeviceSdk()
}
val klleonOndeviceSdk = SdkConfig.sdk
```

### KlleonSdkView

SDK 콘텐츠를 렌더링하기 위한 커스텀 Android View입니다.

```kotlin
@Composable
fun SdkViewComponent() {
    var workerView by remember { mutableStateOf<KlleonSdkView?>(null) }

    AndroidView(
        factory = { context ->
            KlleonSdkView(context).also { view ->
                workerView = view
            }
        },
        modifier = Modifier.fillMaxSize()
    )
}
```

#### setRenderRotation()

TV 등에서 화면 회전이 필요할 때 사용합니다.

```kotlin
klleonSdkView.setRenderRotation(270) // 0, 90, 270도 지원
```

## ResourceManager

리소스 초기화 및 해제를 담당하는 클래스입니다. `play()` 전에 반드시 `init()`으로 리소스를 준비해야 합니다.

```kotlin
val resourceManager = ResourceManager()
```

### init()

아바타 리소스를 캐시 디렉토리로 복사하고, YUV 변환 및 네이티브 메모리 적재를 수행합니다.

```kotlin
resourceManager.init(
    context: Context,
    mp4FileName: String,
    npzFileName: String,
    styleFileName: String = "",
    faceCropYuvFileName: String = "",
    faceCropYuvMetaFileName: String = "",
    avatarId: String = "",
    onSuccess: () -> Unit,
    onError: (Throwable) -> Unit
)
```

**매개변수:**
| 매개변수 | 타입 | 필수 | 설명 |
|---------|------|------|------|
| `context` | Context | O | 현재 컨텍스트 |
| `mp4FileName` | String | O | 아바타 MP4 파일명 (assets 내) |
| `npzFileName` | String | O | 아바타 NPZ 파일명 (assets 내) |
| `styleFileName` | String | X | 스타일 파일명 (기본값: "") |
| `faceCropYuvFileName` | String | X | 사전 추출된 face crop YUV 파일명 (기본값: ""). 제공 시 `warpAffine` 단계 스킵하여 추론 경로 단축 (LIPSYNC-007, v0.6.0) |
| `faceCropYuvMetaFileName` | String | X | face crop YUV 메타 파일명 (기본값: ""). `faceCropYuvFileName`과 함께 사용 |
| `avatarId` | String | X | 아바타 ID. 동일 아바타 재진입 시 버퍼를 재사용하여 즉시 `onSuccess` 반환 |
| `onSuccess` | () -> Unit | O | 리소스 준비 완료 콜백 |
| `onError` | (Throwable) -> Unit | O | 에러 콜백 |

**예제:**
```kotlin
resourceManager.init(
    context = this,
    mp4FileName = "loop_sample.mp4",
    npzFileName = "loop_sample.npz",
    styleFileName = "loop_sample.style",
    avatarId = "character_001",
    onSuccess = {
        // 준비 완료 — play()는 suspend이므로 코루틴에서 호출
        CoroutineScope(Dispatchers.IO).launch {
            klleonOndeviceSdk.play(context, sdkView, sdkKey, avatarId, language)
        }
    },
    onError = { error ->
        Log.e("SDK", "리소스 준비 실패", error)
    }
)
```

:::info 버퍼 재사용
동일한 아바타(`avatarId`)로 `init()`을 재호출하면 이미 준비된 버퍼를 재사용하여 즉시 `onSuccess`를 반환합니다. 다른 아바타로 전환 시에는 이전 버퍼를 해제하고 새로 할당합니다.
:::

### deinit()

네이티브 YUV 버퍼 메모리를 해제하고 리소스 상태를 초기화합니다.

```kotlin
resourceManager.deinit()
```

:::tip 멱등성 보장
`deinit()`은 여러 번 호출해도 안전합니다. 이미 해제된 상태에서 호출하면 no-op입니다.
:::

### 호출 규칙

1. **`init()`** — 아바타 선택 완료 시 호출. 아바타 변경 시 이전 버퍼를 자동 해제합니다.
2. **`play()`** — `init()`의 `onSuccess` 콜백이 왔을 때만 호출 가능
3. **`deinit()`** — 앱 완전 종료 시 호출. `finish()`는 버퍼를 유지하여 동일 아바타 재진입을 최적화합니다.

## SDK 메서드

### play()

AI 아바타 비디오 재생을 시작합니다. `suspend` 함수이므로 코루틴 내에서 호출해야 합니다.

v0.7.0+ `sttMode` 파라미터 추가, v0.8.0+ 기본값 `STT_ONLY`, v0.12.0+ `useMelSpectrogram` 파라미터 추가.

```kotlin
suspend fun play(
    context: Context,
    klleonSdkViewInstance: KlleonSdkView?,
    sdkKey: String,
    avatarId: String,
    language: String,
    sttMode: SttMode = SttMode.STT_ONLY,
    useMelSpectrogram: Boolean = false,
)
```

**매개변수:**
| 매개변수 | 타입 | 필수 | 설명 |
|---------|------|------|------|
| `context` | Context | O | 현재 컨텍스트 |
| `klleonSdkViewInstance` | KlleonSdkView? | O | 렌더링 뷰 |
| `sdkKey` | String | O | SDK 인증 키 |
| `avatarId` | String | O | AI 아바타 ID |
| `language` | String | O | 언어 코드 (`ko_kr`, `en_us`, `ja_jp`) |
| `sttMode` | [SttMode](#sttmode) | X | STT 결과 전달 모드 (기본값 `STT_ONLY` — 앱이 결과 수신 후 `sendMessage()` 명시 호출) |
| `useMelSpectrogram` | Boolean | X | 립싱크 파이프라인 모드 (v0.12.0+, 기본값 `false`). `true`면 MEL 스펙트로그램 경로로 기동하며 [캐시 발화 API](#캐시-발화-api)를 사용할 수 있습니다 |

`voiceRecognitionMode` 가 `ALWAYS_ON` (v0.8.0+ 기본값) 인 경우 `play()` 후 마이크 세션이 자동 시작됩니다. 별도 `startAlwaysOnListening()` 호출 불필요.

**예제:**
```kotlin
CoroutineScope(Dispatchers.IO).launch {
    workerView?.let { view ->
        klleonOndeviceSdk.play(
            context = this@Activity,
            klleonSdkViewInstance = view,
            sdkKey = "YOUR_SDK_KEY",
            avatarId = "character_001",
            language = "ko_kr",
            // sttMode = SttMode.STT_ONLY,  // v0.8.0+ 기본값 (생략 가능)
        )
    }
}
```

### connect()

WebSocket 재연결을 수행합니다.

```kotlin
klleonOndeviceSdk.connect()
```

### finish()

SDK를 중지하고 모든 리소스를 정리합니다. `suspend` 함수이므로 코루틴 내에서 호출해야 합니다.
내부 버퍼는 동일 아바타 재진입 시 재사용을 위해 유지됩니다 (soft reset).

```kotlin
// Activity 종료 시
CoroutineScope(Dispatchers.Default).launch {
    klleonOndeviceSdk.finish()
}
```

### awaitFinish()

진행 중인 `finish()`가 완료될 때까지 대기합니다. 종료 중이 아니면 즉시 반환됩니다.
`finish()` 후 빠르게 `play()`를 재호출하는 경우, `ResourceManager.init()` 전에 호출하여 리소스 경합을 방지합니다.

```kotlin
// 빠른 재진입 시
CoroutineScope(Dispatchers.Default).launch {
    klleonOndeviceSdk.awaitFinish()  // 이전 종료 완료 대기
    ResourceManager.init(context, ...)
}
```

## 메시지 API

### sendMessage()

SDK의 메시징 시스템을 통해 메시지를 전송합니다.

```kotlin
klleonOndeviceSdk.sendMessage(text: String)
```

**예제:**
```kotlin
klleonOndeviceSdk.sendMessage("안녕하세요")
```

### sendMessageEcho()

입력 텍스트를 그대로 TTS + 립싱크로 재생합니다 (LLM 바이패스). 고정 안내 멘트 등에 사용합니다.

```kotlin
klleonOndeviceSdk.sendMessageEcho(text: String)
```

### sendChangeLanguage()

대화 중 언어를 동적으로 변경합니다.

```kotlin
klleonOndeviceSdk.sendChangeLanguage(language: String)
```

**예제:**
```kotlin
// 영어로 변경
klleonOndeviceSdk.sendChangeLanguage("en")
```

### sendStopSpeech()

아바타의 현재 발화를 즉시 중단합니다.

```kotlin
klleonOndeviceSdk.sendStopSpeech()
```

## Chat API

biz-backend `/api/v1/chat` 을 호출합니다. HTTP·인증·이미지 URL 절대화·파싱은 SDK가 처리하고, 호출자는 blocks 만 받습니다. raw app secret key 는 SDK 내부에 갇힙니다.

### chat()

```kotlin
suspend fun chat(
    context: Context,
    text: String,
    lang: String = "ko",
    sessionId: String? = null,
): ChatResult
```

| 매개변수 | 타입 | 필수 | 설명 |
|---------|------|------|------|
| `text` | String | O | 사용자 입력 |
| `lang` | String | X | 응답 언어 (`ko` / `en` / `ja`) |
| `sessionId` | String? | X | 대화 단위 멀티턴 맥락 키. 한 대화 시작 시 UUID 를 만들어 그 대화의 모든 호출에 재사용하고 종료 시 폐기합니다. `null` 이면 서버가 이력 없이 단발로 응답합니다 |

`play()` 세션은 필요 없고 `ResourceManager.init()` 선행만 필요합니다. 결과는 `ChatResult.Success(blocks)` 또는 `ChatResult.Error(error, message)` 이며, `ChatBlock` 은 `Text` / `Image` / `Unknown` 입니다(미지의 type 은 `Unknown` 으로 폴백되어 forward-compat 을 보장).

### ChatBlock.Text.speech

v0.13.0+. 텍스트 block 에 **서버의 캐시 음성 참조**가 실릴 수 있습니다.

```kotlin
data class Text(
    val content: String,
    val speech: CachedSpeechRef? = null,
) : ChatBlock()

data class CachedSpeechRef(
    val fileName: String,   // 예: "Mn38h2DpWyJ2.pcm"
    val format: String?,    // 예: "pcm_s16le_16k"
)
```

`speech` 가 `null` 이 아니면 **서버에 이 답변의 녹음이 있다**는 뜻입니다. 재생하라는 지시가 아니라, 단말이 그 파일을 받아뒀는지 확인할 **조회 키**입니다. 없으면 평소대로 TTS 로 발화하면 됩니다.

```kotlin
val ref = block.speech
if (ref != null && myCache.has(ref.fileName)) {
    klleonOndeviceSdk.speakCachedPcm16Le(myCache.read(ref.fileName))
} else {
    klleonOndeviceSdk.sendMessageEcho(block.content)   // TTS 폴백
}
```

:::info
`fileName` 은 답변 텍스트의 결정적 해시입니다. **직접 계산하지 말고 서버가 준 값을 그대로 조회 키로 쓰세요** — 해시 규칙을 복제하면 조용히 어긋납니다. `format` 은 보조 정보이며 판단 키는 `fileName` 하나입니다.
:::

### setChatBaseUrl()

v0.13.0+. [chat()](#chat) 요청이 나갈 서버를 바꿉니다. 로컬·스테이징 서버 검증용입니다.

```kotlin
fun setChatBaseUrl(url: String?)
```

| 매개변수 | 타입 | 필수 | 설명 |
|---------|------|------|------|
| `url` | String? | O | 예: `http://192.168.0.7:8080`. 끝 슬래시는 자동 제거됩니다. `null`/공백이면 기본 서버로 복귀 |

```kotlin
klleonOndeviceSdk.setChatBaseUrl("http://192.168.0.7:8080")  // 로컬 서버로
klleonOndeviceSdk.setChatBaseUrl(null)                        // 기본 서버로 복귀
```

:::warning
**인증(attestation)은 영향받지 않습니다.** `X-App-Secret-Key` 는 계속 기본 서버에서 발급받고, 지정한 서버는 그 값을 검증만 합니다. 따라서 대상 서버가 같은 app secret 을 알고 있어야 하며, 다르면 chat 이 401 로 실패합니다.

`http` 를 쓰려면 앱의 network security config 에 해당 호스트의 cleartext 허용이 필요합니다. 다음 `chat()` 호출부터 적용됩니다.
:::

## 캐시 발화 API

v0.12.0+. 미리 준비한 PCM 오디오를 서버 왕복 없이 즉시 발화합니다. 인사말·안내 문구처럼 고정된 대사에서 응답 지연을 없앨 때 사용합니다.

**전제**: `play(useMelSpectrogram = true)` 로 기동한 세션에서만 동작합니다. 그 외 세션에서 호출하면 `Result.failure(IllegalStateException)` 을 반환합니다.

### speakCachedAsset()

앱 assets의 PCM 파일을 발화합니다.

```kotlin
suspend fun speakCachedAsset(assetName: String): Result<Int>
```

| 매개변수 | 타입 | 필수 | 설명 |
|---------|------|------|------|
| `assetName` | String | O | assets 내 PCM 파일명 (16kHz mono int16 LE) |

반환값은 발화에 사용된 샘플 수입니다. 실패 시 `Result.failure`.

### speakCachedPcm16Le()

메모리상의 PCM 바이트를 발화합니다.

```kotlin
suspend fun speakCachedPcm16Le(pcmBytes: ByteArray): Result<Int>
```

| 매개변수 | 타입 | 필수 | 설명 |
|---------|------|------|------|
| `pcmBytes` | ByteArray | O | 16kHz mono int16 little-endian PCM (캐시 계약상 16kHz 고정) |

### 캐시 스토어 (v0.13.0+)

SDK 가 캐시 PCM 을 보관하고 보유 여부를 답합니다. `chat()` 응답의 [speech](#chatblocktextspeech) 가 **서버에 있나**를 알려준다면, 이쪽은 **이 단말에 있나**를 답합니다. 파일은 앱 전용 내부 저장소에 보관되어 다른 앱이 접근할 수 없습니다.

```kotlin
fun hasCachedSpeech(context: Context, fileName: String): Boolean
fun importCachedSpeech(context: Context, fileName: String, pcmBytes: ByteArray): Boolean
fun cachedSpeechCount(context: Context): Int
suspend fun speakCachedFile(fileName: String): Result<Int>
```

| 함수 | 설명 | `play()` 필요 |
|------|------|------|
| `hasCachedSpeech` | 보유 여부. 매 응답마다 호출해도 되도록 메모리 조회입니다 | X |
| `importCachedSpeech` | 적재. 16kHz mono int16 LE raw PCM. 같은 이름은 덮어씁니다 | X |
| `cachedSpeechCount` | 보유 개수(진단용) | X |
| `speakCachedFile` | 보유 파일명으로 발화 | **O** (`useMelSpectrogram = true`) |

### speakAnswer()

v0.13.0+. **2단계 판단과 폴백을 SDK 가 대신합니다.** 위 함수들을 직접 조합하는 대신 이걸 쓰면 됩니다.

```kotlin
suspend fun speakAnswer(context: Context, block: ChatBlock.Text): Result<SpeechSource>

enum class SpeechSource { CACHED, TTS, ERROR_NOTICE }
```

| 단계 | 조건 | 결과 |
|---|---|---|
| 1 | 서버가 캐시 파일명을 줬고 + 단말이 보유 | `CACHED` — 로컬 PCM, 서버 왕복 없음 |
| 2 | 그 외이거나 캐시 재생 실패 | `TTS` — 기존 웹소켓 발화 |
| 3 | TTS 도 실패(웹소켓 단절 등) | `ERROR_NOTICE` — 안내 음성만. **답변은 전달 안 됨** |

```kotlin
val first = blocks.filterIsInstance<ChatBlock.Text>().firstOrNull()
first?.let { block ->
    when (klleonOndeviceSdk.speakAnswer(context, block).getOrNull()) {
        SpeechSource.CACHED -> { /* 캐시 적중 */ }
        SpeechSource.TTS -> { /* 일반 경로 */ }
        SpeechSource.ERROR_NOTICE -> { /* 답변 전달 실패 — 화면 안내 등 추가 대응 */ }
        null -> { /* 안내 음성까지 실패 */ }
    }
}
```

:::info
3단계가 있는 이유는 **침묵을 막기 위해서**입니다. 사용자가 말을 걸었는데 아무 소리도 나지 않으면 아바타가 무시한 것으로 보입니다.

1·3단계는 `play(useMelSpectrogram = true)` 세션에서만 동작합니다. 그 외 세션에서는 2단계만 가능하며, 실패 시 `Result.failure` 입니다.
:::

**직접 조합하려면** (`speakAnswer` 를 안 쓰는 경우):
```kotlin
val ref = block.speech                                    // 1차 — 서버에 있나
if (ref != null && sdk.hasCachedSpeech(context, ref.fileName)) {   // 2차 — 단말에 있나
    sdk.speakCachedFile(ref.fileName)                     // 로컬 PCM 발화
} else {
    sdk.sendMessageEcho(block.content)                    // TTS 폴백
}
```

### syncCachedSpeech()

v0.13.0+. 서버의 캐시 음성 목록과 단말 보유분을 맞춥니다 — 없거나 갱신된 것만 내려받고, 서버에서 사라진 것은 지웁니다. 앱 시작 등 원하는 시점에 호출하세요. `play()` 세션은 필요 없습니다.

```kotlin
suspend fun syncCachedSpeech(
    context: Context,
    onProgress: ((done: Int, total: Int) -> Unit)? = null,
): Result<CachedSpeechSyncResult>

data class CachedSpeechSyncResult(
    val remoteTotal: Int, val downloaded: Int, val removed: Int, val failed: Int,
)
```

```kotlin
scope.launch {
    klleonOndeviceSdk.syncCachedSpeech(context) { done, total ->
        updateProgress(done, total)
    }.onSuccess { Log.i(TAG, "동기화: $it") }
}
```

:::info
**[setChatBaseUrl](#setchatbaseurl) 로 지정한 서버에서 받습니다.** 파일명이 `chat()` 응답에서 오므로 자산도 같은 서버여야 이름이 맞습니다.

재다운로드 판정은 서버의 `updated_at` 으로 합니다 — 파일명은 답변 텍스트의 해시라 같은 문장을 다시 녹음해도 이름이 그대로이기 때문입니다.

중단해도 안전합니다(서버 무상태). 다시 호출하면 남은 것부터 이어받습니다. 이미 동기화가 돌고 있으면 즉시 실패를 돌려줍니다. 개별 파일 실패는 `failed` 로 세고 **전체를 중단하지 않습니다**.
:::

:::info
`importCachedSpeech` 는 파일명에 경로 구분자나 `..` 가 있으면 거부합니다. `updatedAt` 을 함께 넘기면 다음 동기화가 그 파일을 최신으로 인정합니다(생략하면 버전 미상으로 보고 한 번 다시 받습니다).

보유 목록에 있어도 파일이 사라졌으면 `speakCachedFile` 이 실패를 돌려주고 목록에서 자동으로 제거합니다. 그때는 TTS 로 폴백하면 됩니다 — `hasCachedSpeech` 가 true 였다고 발화가 보장되지는 않습니다.
:::

### isCachedSpeechReady()

캐시 발화를 사용할 수 있는 상태인지 확인합니다.

```kotlin
fun isCachedSpeechReady(): Boolean
```

**예제:**
```kotlin
CoroutineScope(Dispatchers.IO).launch {
    klleonOndeviceSdk.play(
        context = this@Activity,
        klleonSdkViewInstance = view,
        sdkKey = "YOUR_SDK_KEY",
        avatarId = "character_001",
        language = "ko_kr",
        useMelSpectrogram = true,          // 캐시 발화 전제
    )

    if (klleonOndeviceSdk.isCachedSpeechReady()) {
        klleonOndeviceSdk.speakCachedAsset("greeting_ko.pcm")
            .onFailure { Log.w(TAG, "캐시 발화 실패: ${it.message}") }
    }
}
```

## 런타임 설정 (RuntimeConfig)

v0.12.0+. 재생 중에도 바꿀 수 있는 SDK 동작 토글입니다.

### audioNonStreaming

```kotlin
RuntimeConfig.audioNonStreaming = true   // 기본값
```

- `true`(기본): **논스트리밍** — 발화 하나의 오디오를 끝까지 받은 뒤 한 번에 재생합니다. 중간 버퍼 언더런으로 인한 끊김이 사라지는 대신 첫 소리까지의 지연이 늘어납니다.
- `false`: **스트리밍** — 서버 오디오 청크를 도착하는 대로 재생합니다. 저지연이지만 느린 망에서는 언더런으로 발화가 툭툭 끊길 수 있습니다.

값은 **발화 시작 시점에 캡처**되어 그 발화가 끝날 때까지 고정됩니다(발화 도중 토글해도 섞이지 않음).

> v0.12.0부터 기본값이 논스트리밍입니다. 이전 버전의 재생 동작이 필요하면 `false`로 설정하세요.

## Wakeword API

STT 인식 결과에서 등록된 wakeword를 감지하여 콜백을 전달합니다. Wakeword가 매칭되면 해당 STT 결과는 일반 대화 입력(`STT_RESULT`)에서 제외됩니다.

:::note Standby 연동 정책
Wakeword 매칭은 기본적으로 **비활성화** 상태입니다. `enterStandby()` 호출 시 자동으로 활성화되고, `exitStandby()` 호출 시 자동으로 비활성화됩니다. `registerWakewords()`로 wakeword를 등록하더라도 standby 모드에 진입해야 매칭이 동작합니다.
:::

:::info STT 언어와 wakeword
`play(language)` 또는 `sendChangeLanguage(language)`로 설정한 언어가 STT 인식 언어로도 적용됩니다. Wakeword 매칭은 해당 언어의 STT 인식 결과에서 동작하므로, **각 언어의 STT가 인식할 수 있는 wakeword를 등록**해야 합니다.

예시:
- 한국어 STT → `"영어"`, `"일본어"`, `"니혼고"` 등 한국어 발음 wakeword
- 일본어 STT → `"韓国語"`, `"英語"`, `"コリアン"` 등 일본어 인식 wakeword
- 영어 STT → `"Korean"`, `"Japanese"` 등 영어 wakeword
:::

### registerWakewords()

Wakeword를 등록합니다. 기존 wakeword를 전체 교체합니다. 등록만으로는 매칭이 동작하지 않으며, `enterStandby()` 진입 시 활성화됩니다.

```kotlin
fun registerWakewords(wakewords: Map<String, String>)
```

**매개변수:**
| 매개변수 | 타입 | 설명 |
|---------|------|------|
| `wakewords` | Map\<String, String\> | wakeword → 태그 맵. Wakeword가 감지되면 태그 값이 콜백으로 전달됨 |

**예제:**
```kotlin
// 언어 전환용 wakeword 등록
klleonOndeviceSdk.registerWakewords(mapOf(
    "니혼고" to "ja_jp", "일본어" to "ja_jp",
    "잉글리쉬" to "en_us", "영어" to "en_us",
    "한국어" to "ko_kr", "코리안" to "ko_kr",
))
```

### clearWakewords()

등록된 wakeword를 전체 초기화합니다. 초기화 후에는 wakeword 매칭이 동작하지 않으며, 모든 STT 결과가 `STT_RESULT`로 전달됩니다.

```kotlin
klleonOndeviceSdk.clearWakewords()
```

### wakewordDetected

Wakeword 매칭 결과를 방출하는 `SharedFlow`입니다.

```kotlin
val wakewordDetected: SharedFlow<WakewordResult>
```

**WakewordResult:**
| 필드 | 타입 | 설명 |
|------|------|------|
| `wakeword` | String | 매칭된 wakeword 원문 (예: `"니혼고"`) |
| `tag` | String | 등록 시 지정한 태그 (예: `"ja_jp"`) |
| `fullText` | String | STT가 인식한 전체 텍스트 |

**예제:**
```kotlin
// Wakeword 감지 시 언어 전환
LaunchedEffect(Unit) {
    klleonOndeviceSdk.wakewordDetected.collect { result ->
        // result.wakeword = "니혼고", result.tag = "ja_jp"
        klleonOndeviceSdk.sendChangeLanguage(result.tag)
    }
}
```

:::tip
SDK는 wakeword가 무엇을 의미하는지 관여하지 않습니다. 태그 값은 앱이 자유롭게 정의할 수 있으며, 언어 코드 외에도 `"mode_quiet"`, `"stop"` 등 어떤 문자열이든 사용 가능합니다.
:::

## 대기화면(Standby) API

### enterStandby()

대기화면 모드로 진입합니다. 파이프라인 전체를 정리(큐 비우기, 오디오 버퍼 폐기, 타이밍 초기화)한 후 비디오 디코딩과 오디오 재생을 일시정지합니다. 리소스는 유지됩니다.

```kotlin
klleonOndeviceSdk.enterStandby()
```

### exitStandby()

대기화면 모드를 해제합니다. 비디오 디코딩과 오디오 재생을 재개합니다.

```kotlin
klleonOndeviceSdk.exitStandby()
```

### isStandby()

대기화면 모드 상태인지 확인합니다.

```kotlin
val isStandby: Boolean = klleonOndeviceSdk.isStandby()
```

### setIdleTimeout(timeoutMs)

idle timeout을 활성화합니다. 아바타 발화 종료(TTS_END) 후 지정 시간 동안 무활동 시 자동으로 `enterStandby()`를 호출합니다. `STANDBY_ENTER` 이벤트가 `sdkState`로 발행된 후 대기화면에 진입합니다.

```kotlin
// 기본값 60초
klleonOndeviceSdk.setIdleTimeout()

// 커스텀 timeout (30초)
klleonOndeviceSdk.setIdleTimeout(30_000L)
```

:::info
`play()` 호출 전후 어느 시점에든 호출 가능합니다. 호출하지 않으면 자동 대기화면 기능은 비활성화 상태입니다.
:::

:::note v0.12.1
메시지 전송 후 서버 응답이 오지 않아도 타이머가 멈추지 않습니다. 전송 시점부터 최대 20초 동안 서버 이벤트를 기다리고(응답 watchdog), 아무 응답도 없으면 남은 시간을 무활동으로 계속 셉니다.

**watchdog은 `timeoutMs` 예산 안의 앞구간이며 그 위에 더해지지 않습니다.** 전송 여부와 무관하게 `STANDBY_ENTER`까지의 총 대기는 항상 `timeoutMs`입니다. `timeoutMs`가 20초보다 짧으면 watchdog도 그만큼 줄어듭니다.

v0.12.0 이하에서는 전송 시 타이머가 중지되고 서버 이벤트로만 재시작되어, 응답이 오지 않으면 해당 세션의 idle timeout이 발생하지 않았습니다.
:::

### disableIdleTimeout()

idle timeout을 비활성화합니다. 활성화된 타이머가 있으면 취소됩니다.

```kotlin
klleonOndeviceSdk.disableIdleTimeout()
```

### avatarState: StateFlow\<AvatarState\>

v0.10.3 부터 제공. 아바타의 발화 라이프사이클 상태를 타입드 Flow로 노출합니다. 포괄적인 `sdkState` 문자열 스트림에서 발화 상태만 분리한 값입니다.

```kotlin
enum class AvatarState {
    IDLE,       // 대기
    PREPARING,  // 응답 준비중
    SPEAKING,   // 발화중
}
```

```kotlin
klleonOndeviceSdk.avatarState.collect { state ->
    when (state) {
        AvatarState.IDLE -> { /* 대기 UI */ }
        AvatarState.PREPARING -> { /* 응답 준비중 표시 */ }
        AvatarState.SPEAKING -> { /* 발화중 표시 */ }
    }
}
```

### isResponding: StateFlow\<Boolean\>

아바타가 응답 준비 중이거나 발화 중이면 `true`. v0.10.3 부터 `avatarState != IDLE` 의 파생값입니다(즉 `PREPARING` 또는 `SPEAKING` 일 때 `true`, `IDLE` 일 때 `false`). boolean 동작은 종전과 동일합니다.

```kotlin
// 현재 값 확인
if (klleonOndeviceSdk.isResponding.value) {
    // 아바타 응답 중
}

// Flow로 구독
klleonOndeviceSdk.isResponding.collect { responding ->
    // UI 업데이트
}
```

## 음성 인식 API

v0.8.0 부터 `voiceRecognitionMode` 기본값이 `ALWAYS_ON` 이며, `sttMode` 기본값은 `STT_ONLY` 입니다. `play()` 직후 마이크 세션이 자동 시작되고 STT 결과는 `sdkState` 의 `STT_RESULT` chat_type 으로 전달됩니다 — 앱이 후처리 후 `sendMessage()` 를 호출하는 흐름입니다.

| API | 모드 | 동작 | 활용 |
|---|---|---|---|
| `startAlwaysOnListening` ⭐ | `ALWAYS_ON` | VAD/게이팅 없이 세션 유지, 모든 오디오 STT 전송 | 상시 청취, 연속 대화 (권장) |
| `startVoiceRecognition` ⚠️ Deprecated | `DISCRETE` | VAD 무음 감지 시 자동 종료 (1발화 단위) | Push-to-talk, 단발 명령 — v0.9.0+ 제거 예정 |

### SttMode

STT 인식 결과 전달 모드 enum (v0.7.0+). `play()` 시점에 설정.

```kotlin
enum class SttMode {
    /** STT만 사용 (기본값, v0.8.0+) — 결과를 앱 UI 에만 반환. 서버 LLM 전송 X. */
    STT_ONLY,

    /** STT 결과를 바로 서버로 전송 — 앱 UI + 서버 LLM. */
    @Deprecated("v0.9.0+ 제거 예정. STT_ONLY + sendMessage() 명시 호출 권장.")
    AUTO_SEND_TO_SERVER,
}
```

활용:
- **STT_ONLY** (기본): 앱이 `sdkState` 의 `STT_RESULT` chat_type 수신 → 필터링/검수 → `sendMessage()` 명시 호출.
- **AUTO_SEND_TO_SERVER** (Deprecated): 사용자 발화 → 즉시 AI 응답 (이전 흐름과 호환).

### voiceRecognitionMode

음성 인식 모드를 설정합니다. `play()` 호출 전에 설정해야 합니다.

```kotlin
// v0.8.0+ 기본값이 ALWAYS_ON 이므로 일반적으로 호출 불필요
klleonOndeviceSdk.voiceRecognitionMode = VoiceRecognitionMode.ALWAYS_ON
```

**모드:**
| 모드 | 설명 |
|------|------|
| `ALWAYS_ON` | 상시 리스닝 (v0.8.0+ 기본값). `play()` 후 자동 시작, 세션 유지 |
| `DISCRETE` | 단발 모드. 수동으로 `startVoiceRecognition()` 시작/종료 (Deprecated 흐름) |

### startAlwaysOnListening()

⚠️ **Deprecated (v0.8.0+)** — `startAlwaysOnListening()` 사용 권장. v0.9.0+ 에서 제거 예정.

## 상태 관리

### sdkState

SDK 상태 업데이트를 JSON 문자열로 방출하는 SharedFlow입니다.

```kotlin
klleonOndeviceSdk.sdkState: SharedFlow<String>
```

**사용법:**
```kotlin
klleonOndeviceSdk.sdkState.collect { state ->
    val messageToAdd = try {
        val json = JSONObject(state)
        json.getString("message")
    } catch (t: Throwable) {
        state.toString()
    }

    // 상태 업데이트 처리
    updateUI(messageToAdd)
}
```

**상태 형식 (JSON):**
```json
{
  "message": "",
  "chat_type": "ACTIVATE_VOICE",
  "time": "2025-09-03T05:42:08.394975295",
  "id": "99dd3ab3-53c4-4418-bee4-b1fbaea272aa"
}
```

**주요 chat_type 값:**
| chat_type | 설명 |
|-----------|------|
| `WSS_OPEN` | WebSocket 연결 성공 |
| `WSS_FAILURE` | WebSocket 연결 실패 |
| `WSS_CLOSING` | WebSocket 연결 종료 중 |
| `WSS_CLOSED` | WebSocket 연결 종료됨 |
| `WSS_RETRY_OVER` | 최대 재시도 초과 |
| `WSS_NOT_CONNECTED` | 미연결 상태 |
| `ACTIVATE_VOICE` | 음성 입력 수신 준비 완료 |
| `TEXT` | 서버로부터 텍스트 응답 수신 |
| `RESPONSE_IS_ENDED` | 서버 응답 스트림 종료 |
| `TTS_START` | TTS 음성 재생 시작 |
| `TTS_END` | TTS 음성 재생 완료 (발화 종료 감지에 사용) |
| `SHOW_AVATAR` | 아바타 표시 준비 완료 |
| `USER_SPEECH_STARTED` | 사용자 발화 시작 감지 |
| `USER_SPEECH_STOPPED` | 사용자 발화 종료 감지 |
| `PREPARING_RESPONSE` | 서버 응답 준비 중 |
| `STT_RESULT` | 음성 인식 최종 결과 |
| `STT_PARTIAL` | 음성 인식 중간 결과 |
| `STT_ERROR` | 음성 인식 에러 |
| `STT_STATUS` | 음성 인식 상태 변화 알림 (준비 중/재연결 중/준비 완료) |
| `WORKER_DISCONNECTED` | 소켓 연결 종료 |
| `SPEECH_START` | 아바타 발화 시작 |
| `SPEECH_END` | 아바타 발화 종료 |
| `STOP_RESPONSE_MESSAGE` | 현재 아바타 발화 중단 |

#### STT_STATUS 상세

음성 인식 세션의 일시적 상태 변화를 알려줍니다. 토큰 기반 인증을 사용하는 STT 제공자(Azure 등)에서 발생합니다.

| 상태 | message 값 | 의미 | 발생 시점 |
|------|------------|------|-----------|
| `Preparing` | `음성 인식 준비 중` | 토큰 대기 중으로 인식 시작이 지연됨 | 토큰 미수신 상태에서 음성 인식 시작 시 |
| `Recovering` | `음성 인식 재연결 중` | 인증 실패로 토큰 재발급 대기 중 | 인식 중 인증 토큰 만료 시 |
| `Ready` | `음성 인식 준비 완료` | 복구 완료, 음성 인식 재개 | 토큰 재발급 후 인식 재시작 시 |

:::tip
`STT_STATUS`는 일시적 상태 알림입니다. `음성 인식 준비 중` 또는 `음성 인식 재연결 중` 수신 시 사용자에게 토스트 등으로 안내하고, `음성 인식 준비 완료` 수신 시 자연스럽게 해제하면 됩니다.
:::

## SilenceDetectionConfig

음성 인식 시 무음 감지 동작을 설정합니다.

```kotlin
import io.klleon.ondevice.audio.oboe.SilenceDetectionConfig
```

**필드:**
| 필드 | 타입 | 기본값 | 설명 |
|------|------|--------|------|
| `silenceThreshold` | Float | 0.02 | 무음 판단 레벨 임계값 |
| `speechThreshold` | Float | 0.05 | 음성 판단 레벨 임계값 |
| `speechTimeoutMs` | Long | 5000 | 음성 입력 대기 시간 (ms) |
| `silenceTimeoutMs` | Long | 2000 | 음성 후 무음 감지 시간 (ms) |
| `maxRecordingTimeMs` | Long | 60000 | 최대 녹음 시간 (ms, 0=무제한) |
| `preBufferMs` | Int | 300 | 음성 시작 전 오디오 보존 (ms) |
| `preBufferDelayMs` | Long | 300 | 프리버퍼 플러시 지연 (ms) |

**프리셋:**
| 프리셋 | 특징 |
|--------|------|
| `SilenceDetectionConfig.default()` | 기본 설정 |
| `SilenceDetectionConfig.fast()` | 빠른 응답 (speechTimeout 3초, silenceTimeout 1.5초) |
| `SilenceDetectionConfig.longSpeech()` | 긴 발화 (speechTimeout 7초, silenceTimeout 3초, maxRecording 120초) |
| `SilenceDetectionConfig.noisyEnvironment()` | 소음 환경 (임계값 상향: silence 0.05, speech 0.10) |

**예제:**
```kotlin
// 프리셋 사용
klleonOndeviceSdk.startVoiceRecognition(SilenceDetectionConfig.fast())

// 커스텀 설정
val config = SilenceDetectionConfig.default().copy(
    speechTimeoutMs = 3000L,
    maxRecordingTimeMs = 120_000L
)
klleonOndeviceSdk.startVoiceRecognition(config)
```

## 라이프사이클 관리

`play()`와 `finish()`는 `suspend` 함수입니다. Activity 라이프사이클에서는 코루틴으로 래핑하여 호출합니다.

```kotlin
class ChatActivity : ComponentActivity() {
    private val sdk = SdkConfig.sdk

    override fun onDestroy() {
        super.onDestroy()
        // finish()는 suspend이므로 코루틴에서 실행
        CoroutineScope(Dispatchers.Default).launch {
            sdk.finish()  // SDK 정지 (버퍼는 재사용을 위해 유지)
        }
        ResourceManager.deinit()  // 앱 완전 종료 시에만 호출
    }
}
```

### 빠른 재진입 (finish → play)

`finish()` 후 곧바로 `play()`를 호출하면 리소스 경합이 발생할 수 있습니다.
`awaitFinish()`를 사용하여 이전 종료가 완료된 후 진행하세요:

```kotlin
// 캐릭터 선택 화면에서 새 아바타 시작 시
CoroutineScope(Dispatchers.Default).launch {
    sdk.awaitFinish()  // 이전 finish()가 진행 중이면 완료 대기
    ResourceManager.init(context, mp4, npz, style, avatarId,
        onSuccess = { /* ChatActivity 시작 → play() */ },
        onError = { /* 에러 처리 */ }
    )
}
```
