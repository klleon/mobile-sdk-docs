# 릴리스 노트

Klleon Ondevice SDK의 버전별 변경사항입니다.

---

## v0.12.0 (Latest)

**릴리스일**: 2026년 8월

### 새로운 기능
- `play()`에 `useMelSpectrogram: Boolean = false` 파라미터 추가 — MEL 스펙트로그램 기반 립싱크 파이프라인으로 전환하는 모드 스위치. `false`(기본)는 기존 AUDIO_FEATURE 경로 그대로.
- 캐시 발화 API 추가: `speakCachedAsset(assetName: String): Result<Int>`, `speakCachedPcm16Le(pcmBytes: ByteArray): Result<Int>`, `isCachedSpeechReady(): Boolean`. 미리 준비한 PCM(16kHz mono int16 LE)을 서버 왕복 없이 즉시 발화한다. `play(useMelSpectrogram = true)` 세션에서만 동작.
- `RuntimeConfig.audioNonStreaming` 추가 — 발화 오디오를 끝까지 받은 뒤 한 번에 재생(기본 `true`). 중간 버퍼 언더런으로 인한 끊김이 사라지는 대신 첫 소리 지연이 늘어난다. `false`로 두면 기존 스트리밍 재생.
- 서버 PCM→MEL 라이브 발화: 서버가 보낸 PCM을 단일 ordered 스트림으로 소비하고, 연결 세대(cid) 기반 가드로 재연결 시 이전 세션 잔여 이벤트를 차단.
- 세션 계측 통합: `SESSION_VITALS` 단일 이벤트로 네트워크·디바이스 상태를 New Relic에 적재(회선 속도 측정 3분 주기, 1.5MB cap).

### 동작 변경
- **오디오 재생이 논스트리밍 기본**입니다. API 변경 없이 업그레이드만으로 재생 방식이 바뀝니다. 이전 동작이 필요하면 `RuntimeConfig.audioNonStreaming = false`.
- `play()`의 default 파라미터 추가는 **소스 호환이지만 바이너리 비호환**입니다. 소비자 앱 재컴파일이 필요합니다(Gradle 의존성 갱신 시 자동).

### 버그 수정
- 발화 중단(`sendStopSpeech`)과 새 발화 시작이 겹칠 때의 경합 차단 — stop epoch 도입, 중단 후 오디오 재적재 차단, 정리 순서 교정.
- WebSocket 재연결 시 이전 소켓의 stale 메시지·콜백이 새 세션 상태를 오염시키던 문제 이중 방어. 연결 종료 신호(Disconnected)는 지연 도착해도 반드시 전달.
- 발화 도중 연결이 끊겼다 복구되면 첫 발화가 `reset()`/`TTS_START` 없이 진행돼 이전 발화 잔여 오디오와 섞이던 문제 수정.

## v0.10.0

**릴리스일**: 2026년 6월

### Breaking Changes (STT SPI)
- `SttProvider` 계약 재정의: `startSession`/`endSession`/`release`/`onServerEvent` → `connect`/`disconnect`/`close`/`setEventSink`/`updateToken`.

## v0.8.0

**릴리스일**: 2026년 5월

### Breaking Changes
- `KlleonOndeviceSdk.voiceRecognitionMode` 기본값 `DISCRETE` → `ALWAYS_ON`. `play()` 직후 마이크 세션이 자동 시작된다. DISCRETE 흐름을 유지하려면 `play()` 호출 전에 `sdk.voiceRecognitionMode = VoiceRecognitionMode.DISCRETE` 를 명시.
- `KlleonOndeviceSdk.play()` 의 `sttMode` 기본값 `AUTO_SEND_TO_SERVER` → `STT_ONLY`. STT 결과가 서버로 자동 전송되지 않으며, 앱이 `sdkState` 의 `STT_RESULT` chat_type 수신 후 `sendMessage()` 를 명시 호출해야 한다. 자동 전송을 유지하려면 `sttMode = SttMode.AUTO_SEND_TO_SERVER` 를 명시.
- `startVoiceRecognition()` `@Deprecated` — DISCRETE 모드 전용. `startAlwaysOnListening()` 사용 권장. v0.9.0+ 에서 제거 예정.
- `SttMode.AUTO_SEND_TO_SERVER` `@Deprecated` — `STT_ONLY` 사용 권장. v0.9.0+ 에서 제거 예정.

### 마이그레이션
자세한 절차는 [가이드 → v0.6.0 → v0.8.0 마이그레이션](/category/04-guides) 참고.

### 빌드 변경
- `sttProvider` 기본값 `agora` → `azure` (Azure Direct STT 권장)
- debug `ATTEST_BASE_URL` 을 dev EKS (`https://dev.ondevice-biz.klleon.io`) 로 통일. 사내 LAN dev 머신 검증 시 build script 내 주석 라인으로 임시 교체.

## v0.7.0

**릴리스일**: 2026년 5월

### Breaking Changes
- `AgoraSttProvider` `@Deprecated` — Azure Direct STT 권장. Agora Relay STT 는 미래 제거 예정.
- `VoiceServerBridge.sendRecognizedText()` 제거 — STT 결과 서버 전송 분기가 `SttSessionManager` 로 통합. 외부 호출자는 없었음 (SDK 내부 API).

### 새로운 기능
- **`SttMode` enum 도입** (`STT_ONLY` / `AUTO_SEND_TO_SERVER`) — `play()` 의 신규 파라미터. 본 버전 기본값은 `AUTO_SEND_TO_SERVER` (v0.8.0 에서 `STT_ONLY` 로 전환).
- **AppToken V2 attestation**: challenge-token → app-attest OkHttp 흐름 → `app_secret_key` 24h cache (`SecureAttestStorage`). `ResourceManager.init()` 내부에서 `AppToken.initialize()` 자동 호출.
- `ChatType.STT_AUTH_ERROR` / `SignalType.STT_AUTH_ERROR` 신규 — STT 토큰 V2 인증 실패 (`STT_ERROR` 와 분리).
- 모델 복호화 키 V1 cert hash → V2 `app_secret_key` 전환 (`ServerKeyProvider` 신규, `SignatureBasedKeyProvider` 제거).

### 변경사항
- STT 토큰 fetch 시 `X-App-Secret-Key` 헤더 사용, 401 시 1회 retry, 403 즉시 surface.

## v0.5.0

**릴리스일**: 2026년 4월

### Breaking Changes
- `pauseVideo()` / `resumeVideo()` / `isVideoPaused()` → `enterStandby()` / `exitStandby()` / `isStandby()`로 리네이밍
- `registerKeywords()` / `clearKeywords()` / `keywordDetected` → `registerWakewords()` / `clearWakewords()` / `wakewordDetected`로 리네이밍

### 새로운 기능
- 대기화면(Standby) 모드: 파이프라인 전체 flush + 타이밍 재초기화로 빨리감기/ANR 방지
- Wake-word 매칭: STT 인식 결과에서 등록된 키워드 감지 → 콜백 전달 (standby 중에만 활성)
- `setIdleTimeout()` / `disableIdleTimeout()`: TTS_END 후 무활동 시 자동 대기화면 진입
- `isResponding: StateFlow<Boolean>`: 아바타 응답 상태 추적 (PREPARING_RESPONSE ~ TTS_END)
- `STANDBY_ENTER` 이벤트: 자동 대기화면 진입 시 sdkState로 발행

### 버그 수정
- VideoDecoder `stop()` race condition (pauseToken/stopToken 순서 역전)
- ASYNC 모드 consumer가 pauseToken 미확인
- AudioPlayer `pause()` / `resume()` 추가 (비디오만 멈추고 오디오 계속 재생 문제)
